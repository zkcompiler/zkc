# F0-V2B2C1B1 foundation owner projections

This package executes the first constructor-isolation slice of B2C1B. It
extends the B2C0 canonical-byte admission substrate with four foundation
families and projects all six normalized B2B owner views through the exact
B2C1A value codec.

Run from the repository root:

```sh
python3 -B evaluation/formal-source-owner-projections-f0v2b2c1b1/run.py --check
```

The scoped result is
`Affirmative/F0V2B2C1B1-A-FOUNDATION-OWNER-PROJECTIONS`: a reference owner
evaluator and a separately structured cold byte-derived projector agree on 36
distinct exact view bodies over six minimal carriers. This closes four of the
21 B2C pressure families at bounded research resolution. It does not close
the other seventeen families or either B2D integration family.

## Covered slice

The four covered families are:

- verifier-private dependency, discriminating unused and terminal-observed
  private sources, plus refusal of a private-derived public binding;
- constant and derived values;
- child scopes with a nontrivial guard; and
- deterministic Verifier messages visible to a later Prover decision.

Every positive Core is admitted from exact canonical bytes into an immutable,
alias-free owner snapshot. A Fresh Protocol is then admitted under the same
extended evaluator fingerprint and exact Core/closure pairing. The reference
path projects from retained owner facts. The cold path starts only from
complete profiled Core and Protocol bytes plus their exact references,
independently authenticates both identities, profile equality, Fresh
interpretation, and the Protocol-to-Core dependency, then uses separate K1,
schema-compiler, parser, graph, projector, and iterative-codec module
instances to rederive the same six bodies.

All 36 bodies fully decode and re-encode, repeated projection is stable, and
every inhabited sorted-unique sequence follows exact encoded child-body
order. Negative controls cover wrong derived and Verifier-message ABIs,
unsupported guard implication, binding-before-producer availability,
private-derived public binding, unsupported Challenge input, cross-Core Fresh
pairing, foreign evaluator and Protocol-closure authority, edge-order
substitution, a schema-valid eligibility flip,
truncated owner bytes, Core and Protocol body/reference substitution, a
self-authenticating Protocol for another Core, and a Protocol-reference kind
substitution.

## Design corrections retained by the gate

The executable package records four distinctions that a target publication
must preserve:

1. `verifier_private_predecessors` contains only private input source nodes
   that reach a sink. Private-tainted descendants remain in the PCGraph class
   table; they are not duplicated in this field.
2. Public sinks retain the exact observation coordinate. A binding may carry
   already-public history and uses its `BindingObservationNode`. A value with
   verifier-private ancestry is refused by Core admission rather than treated
   as an eligible public binding. A deterministic Verifier result uses its
   `OccurrenceOutputNode`, and a terminal public output uses its value-producer
   node in addition to the `TerminalDecisionNode`.
3. A binding in a scope opened before an occurrence cannot read that
   occurrence's output.
4. A Fresh handle used by this projection slice must be issued by the same
   extended evaluator as its Core handle; a predecessor evaluator capability
   is authentic but insufficient.

These are candidate owner-law corrections discovered by research evidence,
not edits to authoritative PIR semantics.

## Boundary

The 39 frozen findings include fifteen scoped affirmatives and explicit
`CannotAnswer` outcomes for the eight Oracle families, five
claim/reduction/challenge families, three module-effect families, one expanded
terminal family, both B2D integration families, target publication, live
implementation correspondence, formal proof, security, and Q1.

The package does not publish a target profile, prove that the normalized
schemas are sufficient for every future Analysis question, validate a current
compiler/runtime implementation, execute an Oracle, establish integrated
PCGraph or runtime-receipt closure, prove a theorem, or establish a
Fiat--Shamir or other cryptographic property.
