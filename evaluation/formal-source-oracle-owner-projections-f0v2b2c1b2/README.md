# F0-V2B2C1B2 Oracle owner projections

This package executes the Oracle constructor-isolation slice of B2C1B. It
extends the canonical-byte owner evaluator over all eight Oracle pressure
families and projects each admitted Core and paired Fresh Protocol into the
six candidate normalized B2B owner views through the exact B2C1A codec.

Run from the repository root:

```sh
python3 -B evaluation/formal-source-oracle-owner-projections-f0v2b2c1b2/run.py --check
```

The scoped result is
`Affirmative/F0V2B2C1B2-A-ORACLE-OWNER-PROJECTIONS`: a typed owner evaluator
and a separately structured cold byte-derived projector agree on 48 distinct
exact view bodies over eight minimal carriers. A ninth discriminator carrier
also agrees across both paths and demonstrates that an admitted logical-Oracle
Core may pair with a valid Fresh Protocol while remaining structurally
ineligible for same-Core Fiat--Shamir when its influence reaches acceptance.

## Covered slice

The eight covered B2C families are the complete product of Initial versus
Prover origin and FullCanonical, PublicBinding, or LogicalAccess publication,
plus Public and VerifierOnly query/answer visibility. The gate checks:

- strict Core bytes, exact profile and identity authentication, retained
  immutable owner facts, and same-evaluator Fresh pairing;
- origin-specific strategy decisions, all three publication arities and
  carrier/lookup types, exact lifecycle backlinks, and the three static Oracle
  receipt-schema branches;
- authenticated binding algorithms and evaluation contracts, exact binding
  ABI, and finite canonical domain-law ordering;
- publication-to-query, index-to-query, query-to-answer, and
  publication-to-answer PCGraph edges;
- node-local transfers: a causal publication edge is retained but is not an
  extra input to `Join(activity,index)`, while public Answer uses
  `Publish(activity)`;
- Public publication/query/answer reads for a later Prover decision and
  exclusion of VerifierOnly coordinates;
- VerifierPrivate propagation to a dependent sink and both empty and nonempty
  logical-access acceptance intersections; and
- exact target-body collection order, full round trips, deterministic
  reprojection, and byte-for-byte reference/cold agreement.

The cold path imports neither the typed Oracle model nor its object graph. It
authenticates complete profiled Core and Protocol bodies against exact
references, checks Fresh-to-Core pairing, parses plain records, and uses
separate Foundation, schema, graph, projection, and codec module instances.

## Negative controls

The 44 frozen findings include refusals for duplicate publication and Answer,
Answer scope mismatch, Answer after an active terminal, noncanonical domain
law order, schema-valid origin, move, logical-publication-arity, and receipt-
visibility substitutions, truncated owner bytes, body/reference substitution,
cross-Core Protocol substitution, and predecessor-evaluator authority.
Binding ABI and declaration-kind substitutions return `KindMismatch`.

An Answer has no authored visibility field. Its visibility is derived from the
referenced Query, so the gate tests exact Query backlink and scope rather than
pretending to compare two independently supplied visibility labels.

## Boundary

`ExecutionView` contains owner-derived static record schemas only. This package
does not execute an Oracle, consume an initial-Oracle capability, obtain a
Prover carrier, evaluate a binding, perform lookup, construct a completed run
record, or replay any receipt. Those runtime checks remain in B2D.

The result closes eight more of the 21 B2C pressure families at bounded
research resolution. Nine B2C families and both B2D integration families
remain. It does not publish a target profile, establish current compiler or
runtime correspondence, prove the projection law, establish binding or hiding,
prove Fiat--Shamir security, or close F1 Q1.
