# Analysis named-premise owner-text review

This package independently reviews whether the proposed Analysis named-premise
owner text is closed enough to freeze. Its one exact question is:

> Does the reviewed owner-text range define every name and law family it uses,
> keep all affected constructors field-complete, preserve the selected
> fail-closed intake and semantic decisions, form all seven Schnorr premise
> coordinates, publish consistent profile manifests and revisions, and provide
> enough information to refreeze every affected Analysis evaluation package?

Run from the repository root:

```sh
python3 -B evaluation/formal-source-analysis-premise-review-f0v2d1/run.py --check
```

The frozen aggregate is
`Negative/F0V2D1-N-ANALYSIS-PREMISE-TEXT-NOT-CLOSED`. The checker reproduces
ten findings, including the seven requested review answers, from the owner
pages, profile manifests, independent publication compilers, predecessor
probe, finite Schnorr candidate, and current Analysis reference model.

## What the check covers

The checker:

- searches the allowed Analysis, Relations, Protocol IR, and Foundation pages
  for every requested definition and law-family name;
- enumerates every displayed Analysis question, goal, hypothesis-context,
  support, judgment, and named-premise body constructor and checks the newly
  required fields;
- checks the written intake partition for missing sources, kind or coordinate
  mismatches, malformed key sets, all four model scopes, and absence of a
  default branch;
- checks the seven Schnorr slots against the subject tuple, Relations witness
  binding, Plan key types, and the finite candidate ordinals;
- compares all three literal supported-kind catalogs with their manifests,
  audits revision changes against the review base, and runs both publication
  compilers on current and reconstructed base source; and
- inventories the exact Analysis reference classes, constructor calls, and
  dependent evaluation packages that require migration or revalidation.

## Result boundary

A passing package run means only that the frozen negative review is reproduced
from the pinned working-tree sources. It does not mean that the owner text is
accepted, repaired, published, or implemented. It does not prove name closure
beyond the selected source syntax, profile-law correctness, provider
correspondence, relation satisfaction, Plan honesty, theorem truth,
cryptographic security, compiler correctness, or production validity.

The two publication compilers agreeing on eighteen profile bodies establishes
finite reconstruction agreement and the exact six-profile rotation cone. It
does not override the name, constructor, manifest-sequence, or revision
findings. Missing premise bindings for existing questions remain
`CannotAnswer`; the checker never fills them with empty or ambient defaults.
