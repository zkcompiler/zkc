# F0-V2B2A constructor-closure census

This gate authenticates the current Interaction source through both semantic-
profile publication implementations, extracts its fourteen-field Core root,
and checks a closed census of the constructor and derived semantic algebras
that a constructor-complete six-view grammar must cover.

Run from the repository root:

```sh
python3 -B evaluation/formal-source-constructor-closure-f0v2b2a/run.py --check
```

The frozen result is
`CannotAnswer/F0V2B2A-C-EXECUTABLE-CONSTRUCTOR-CLOSURE`. Its 44 findings
contain eight affirmative census/program results, eight open executable
obligations, and twenty-eight refused inventory mutations.

The authenticated census contains:

- the exact fourteen `InteractiveCore` root fields;
- sixteen Appendix-A canonical variant tables with 57 cases;
- five derived semantic algebras with 22 cases;
- twenty missing B1 variant cases and eight maximum-zero B1 references;
- fourteen required schema-repair groups;
- twenty-three positive/negative pressure families covering all six views;
- four bounded reuse sources; and
- eight explicitly prohibited shortcuts.

The principal finding is methodological. F0-V2B2 should not be one large
fixture. The checked program separates:

```text
B2A  source census and exact B1 delta                    [this gate]
B2B  complete schema source plus constructor inhabitance
B2C  isolated admitted carriers plus owner projections
B2D  integrated carrier plus full PCGraph transfer pressure
```

This order prevents a green integrated fixture from hiding an uninhabited
schema branch, an unsupported admission branch, or a compensating graph error.
The Oracle pressure is the full two-origin by three-publication-mode product,
with both query visibilities. Module effects separately exercise all three
decision classes. Claims, reductions, joint/shared challenges, terminal
dispositions, private dependencies, and Fresh runtime Oracle receipts each
have a named negative discriminator.

The package may reuse F1-R1B identity and admitted-handle machinery, native
Oracle scenarios, downstream claim/reduction scenarios, and module-surface
pressure. Their carriers and judgments do not substitute for an exact target
Core evaluator. In particular, F1-R1B still represents Oracle and Reduction
fields as opaque tuples and supports only four of the eight effect variants.

This gate does not define the B2 schema, inhabit a constructor, admit an
extended Core, derive an owner view, validate a general `PCGraph`, publish a
target profile, establish implementation correspondence, or make a formal or
cryptographic claim.
