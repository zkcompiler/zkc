# Checked physical table reference

This executable Lean client represents a table evaluation as either a deferred
query or a materialized scalar in immutable storage. A scalar reference is read
in the actual final store. The existing `Source.Region` grammar supplies control;
there is no second copy of its branch, loop or shared-continuation constructors.

| Module | Responsibility |
|---|---|
| [Storage](Storage.lean) | Immediate scalars, deferred/materialized cells, publication and preservation of old reads |
| [Language](Language.lean) | Explicit `prepare`/`invoke` operations, physical values/state, logical projection and execution |
| [Simulation](Simulation.lean) | Local operation laws and complete region correspondence |
| [Checking](Checking.lean) | Independently decode the actual candidate and check logical folding of its projection against the retained source; embed logical inputs |
| [Admission](Admission.lean) | Transport logical call instrumentation and source phase admission to the checked physical body |
| [Format](Format.lean) | Separate experimental wire profile, exact source context and installed dependency selection |
| [Tool](../../Tools/TablePhysical.lean) | Compile the reference candidate, check it, bind supplied inputs and execute it |

`RegionSimulation.run` in the [maintained realization library](../../Zkc/Realization/RegionSimulation.lean)
lifts heterogeneous operation laws through compact control. In addition to each
new result, the local law preserves every old represented value. This matters
when a continuation reads a captured reference after another allocation.
[Controls](../../Tests/TablePhysical.lean) show that a corrupting overwrite can
satisfy local returned-value/state/event correspondence while violating this
frame. The frame also survives terminal stops.

`Checked.correct` concerns the submitted physical body, not merely a candidate
regenerated by the producer. It relates the complete logical execution to the
physical execution for every related input and store, and any logical handler,
state and event types. Preparation choices may
differ between occurrences. Input embedding works for every logical input;
external JSON inputs retain the existing finite table client's rank-12 limit.

The checker retains partial operations, arguments, order, shape guards and
control structure. It permits representation choice, including ordinary eager
`invoke evaluate`, and the installed total law `linear(a, a, r) → a`. Logical
folding compares independently normalized source and candidate projection; the
source itself is retained for admission. It does not authorize deleting or
merging evaluations. An unused invalid evaluation still refuses before a
following provider call. [Changed-candidate controls](../../Tests/TableOptimization.lean)
cover alias chains, shared suffixes, original certificates and invalid deletions.

Run from the repository root after building the tool in `formal`:

```sh
formal/.lake/build/bin/table-physical-reference lower lazy examples/tables/source.json > /tmp/table-lazy.json
formal/.lake/build/bin/table-physical-reference check examples/tables/source.json /tmp/table-lazy.json
formal/.lake/build/bin/table-physical-reference run examples/tables/source.json /tmp/table-lazy.json examples/tables/inputs.json
```

Replace `lazy` with `materialized` for the other choice. Execution reports the
complete logical observation and separate table-evaluation/cell counts. A
returned reference is decoded against its completion store, including that
final read in the evaluation count. Counts are instrumentation of this reference,
not proved native costs, elapsed time or a universal profitability claim.

The `lower` command retains the Lean-only `zkc-table-physical-reference` profile.
The same checker/evaluator also accepts `zkc-table-physical-plan`, emitted by
MLIR and consumed by the Rust `run-physical` command. Its acknowledgement names
the selected realization, so a direct or reference-only receipt cannot admit a
native physical candidate. Both formats use the same typed body and theorem;
the new format tag does not extend the theorem to compiled Rust.

For a native physical candidate, `admit` and `run-admitted` additionally accept
the installed `table-round/1` profile and source certificate. `admit-entry` and
`run-entry` consume `table-endpoint/1` with an explicit actor/phase entry. Both
tools share policy resolution in [TableAdmission](../../Tools/TableAdmission.lean).
The physical tool validates the actual endpoint state before binding inputs.
The interpreter's fallback for an undecodable operand is `.stopped .refused`.
Related inputs and the immutable frame make that branch unreachable in the
correspondence theorem. Native invalid references remain host errors; that
fallback does not identify them with a protocol stop.

`Checked.audit_correct` instantiates the general simulation with the existing
logical `ExecutionPath.handler`. Its call audit and final phase survive physical
execution. `calls_permitted` and `return_permitted` combine that correspondence
with the source checker's all-typed-reply laws. Preparation and scalar reads make
no logical provider calls. A stopped call retains its actual state/events and
entry phase, even with a provider different from the deterministic fixture.
[Admission controls](../../Tests/TablePhysicalAdmission.lean) include a false send
reply and a stopped draw that changes state and emits an event.

The reference's scalar store is unbounded and lacks
native issuer/generation identity; tables, residuals and points remain mathematical
values. Ordinary invocation uses the existing finite two-field kernel/provider
meaning. The native implementation supplies storage and bounded admission,
validated by differential execution. Differential tests connect that phase result
to owned native endpoints. Native formal verification, arbitrary operation
expansion, general endpoint admission and protocol security remain outside this
result.
