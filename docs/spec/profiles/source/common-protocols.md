# Resolved common protocols

This profile gives executable meaning to common source containing role-local
computations, messages and shared protocol calls. It composes
[resolved local definitions](definitions.md) and
[located execution](located-execution.md) through the existing `PIR.Proc` meaning.
It does not add an execution kernel or replace the construction, participant and
physical-plan abstraction boundaries.

The maintained modules are
[`Syntax`](../../../../formal/Zkc/Source/Protocol/Syntax.lean),
[`Meaning`](../../../../formal/Zkc/Source/Protocol/Meaning.lean) and
[`Execution`](../../../../formal/Zkc/Source/Protocol/Execution.lean).
The resolved interpretation uses natural-number counts. The same typed grammar
also supports [symbolic counted templates](families.md); instantiation preserves
structure and commutes with both projections. Global branches, role
remapping, portable name/input resolution and participant generation remain
outside this implementation.

## Ports and definitions

Fix role, binding, entry and schema types, a domain language `L`, and its value
interpretation `Value : L.Ty -> Type`. A port is `(role, sort)`. A context is an
ordered list of ports; an operand must match both fields. The underlying value
is `Value sort`, so a received field element can share its domain representation
with a sent element without sharing its binding or ownership.
The role tag denotes the participant-local port, not exclusive ownership of the
mathematical value or permission to duplicate a linear resource.

Local definitions use the existing acyclic table of `Region` bodies. A local
call at role `r` requires arguments with ports `(r, argumentSort)` and binds its
result at `(r, resultSort)`. Domain sorts may represent structured objects;
they are not restricted to scalar arithmetic. Local branches and loops remain
inside those bodies. Local-effect conformance is an additional requirement on
the actual selected interpretation, as specified by the located-call profile.

A protocol signature has ordered argument and result **port lists**. Its body
can use multiple roles and invoke earlier protocol definitions. A callee starts
with only its declared arguments. On normal return, the declared result tuple
is prepended to the retained caller context. A value's presence in that context
does not authorize returning it under another role's port.

An instance contains a typed reference to an actual protocol body and a separate
binding key. Invocation selects that body's key and extends the path with the
call site. The caller's continuation resumes under the caller's original key
and path. Sharing a definition neither resets role state nor allocates resources.
Recursive symbol cycles are not part of this acyclic subset.

## Structured meaning

For a current context `Γ` and final result ports `R`, the constructors mean:

| Constructor | Meaning |
|---|---|
| `ret operands` | Return the actual ordered values at their declared ports |
| `stop site role reason` | Stop the joint reference with this role/site origin |
| `localCall site role callee args next` | Execute the stored local body, then bind its result at that role |
| `pure site role captures body next` | Evaluate the closed total region and bind its immutable results at that role, without a local-service action |
| `query site role root args next` | Perform one ordered service query against the closed root's current state and bind its reply at that role |
| `guard site role condition next` | Continue when the role's Boolean condition is true; otherwise stop with rejection at that role/site |
| `message site schema sender receiver value next` | Send the sender's value, receive independently, then bind the actual received value at the receiver |
| `invoke site instance args next` | Execute the actual stored protocol and bind its ordered result ports |
| `repeat site count initial body next` | Retain one body; feed its returned accumulator ports into each succeeding iteration |
| `bind body next` | Sequence a body with a shared continuation and ordered result binding |

Messages require distinct sender and receiver roles. Their schema key is passed
to the selected runtime; matching domain sorts alone do not establish a codec
or schema conformance law. The received value need not equal the sent value.

A loop's count is a fixed natural number in the resolved source instance. Its
body sees the current accumulator ports followed by the original captures and
must return those accumulator ports. The next iteration receives the actual
returned values. Zero iterations retain the initial values. Iteration frames
start at zero and are appended outside any child-invocation frames. The syntax
stores one loop body; its denotation does not require syntactic unrolling.

Paths are generated by invocation/iteration traversal. Primitive origins retain
the entry label, selected binding key, current path, role and source site.
These are diagnostic values. Distinct source-site labels and stable entry/key
resolution still require formation; the record is not a collision-free artifact
identity or a cryptographic transcript encoding.

`Definitions.denote_here` identifies the actual stored body. `Program.run_invoke`
states complete child execution followed by ordered result binding;
`run_invoke_stopped` retains the stopped child's actual state and events and
does not execute the parent's normal suffix.

## Inline pure regions

A pure region has explicit typed captures and typed output bindings. Captures
refer to existing values at its role and are the complete region environment.
Its operations resolve to positively total logical contracts. Every input,
intermediate and output type must permit copying and dropping. Its terminal
yield must match the declared output types and order. No query, message, guard,
opaque call, release or stop is a pure instruction. The initial executable
subset uses attribute-free closed operations; broader graph constructors retain
their separate mathematical admission obligations.

The denotation is ordinary total evaluation, followed by the continuation with
the resulting values. Replication at available roles uses the same operation
interpretation. Native allocation, codecs, group kernels and entropy providers
have separate adequacy and resource premises. Mathematical totality does not
classify their physical failures as impossible.

Placement and projection retain the inline body. Outlining at realization is
governed by the [pure-call folding relation](../compiler/mathematical-placement.md#inline-pure-regions-and-outlining),
which checks the actual introduced helper. An original opaque call cannot be
treated as pure merely because it has the same signature or name.

## Closed roots and ordered guards

A closed root fixes a service declaration and its permitted roles. It is a
semantic identity, not a data operand. Every occurrence naming one root accesses
that root's current state, including occurrences reached through aliased
capability parameters. Two queries are two ordered occurrences even if their
arguments and replies agree. Distinct root identities do not by themselves
establish probabilistic independence.

The located form uses actual module roles and already resolved roots. A query
must name an admitted service, use an authorized role, and match the service's
request/reply signature. The initial entropy service has no request operands
and one immutable scalar reply. Full-field nonce sampling and nonzero-field
challenge sampling are different declarations and result types. The service
interpretation supplies its sampling law; admission alone does not prove that
law or a native implementation's distribution.

Projection retains the root identity table and emits each query only at its
owner. It preserves occurrence order and binds the actual service reply. The
root table does not grant access to another role's query result. Native
realization must relate each root to its actual authenticated state interface,
thread every successful successor exactly once, and retain the stopped
post-state after a failed query. Hidden state lookup cannot replace that
interface obligation.

A guard reads an available Boolean at its owner. It neither returns a Boolean
result nor requests an arbitrary service reply. False stops before the normal
suffix; true runs that suffix. Projection erases a foreign guard from an
independent participant. Any joint cancellation of peers after rejection is a
separate host policy. Guards cannot occur inside total pure regions or be
removed by pure-call folding.

## Runtime boundary

`Runtime.run` takes actual local/protocol tables, a selected typed instance,
an entry label, ordered input values and separate role states. It starts at the
root path and uses the selected interpretation of local primitive operations.
Protocol bodies come from the source table, not runtime body callbacks.

The runtime chooses local primitive implementations by binding key and role.
Each implementation fixes its operation interpretation and handler before
execution and receives only that role's state. Roles may have different state
and event types. The joint observer records the complete state family and tags
events with their origins; this observer is not an endpoint's permitted view.

A message runs two actions in sequence. `send` receives only the sender's state
and returns a packet or a stop. On success, `receive` receives that packet and
only the receiver's state. Its actual result becomes the new receiver operand.
The packet family is supplied by the runtime; this profile does not mandate a
wire encoding or prove delivery behavior.

`message_send_stopped` proves that a failed send retains its effects and never
runs reception. `message_receive_stopped`, for distinct roles, retains both the
successful sender effects and the failed receiver's actual post-state/events.
The stopped origin is the receiver's. Local failures, including empty-event
stops, retain the corresponding located origin. No normal continuation runs
after a stop.

This is a synchronous joint reference. Local calls are atomic relative to peers;
send precedes receive. It does not establish native scheduling, peer notification,
cancellation, information-flow security or backend implementation correctness.
Raw execution also does not prove the selected local-effect, sampling, resource
or codec contracts. Such admission uses the existing contract machinery.

## Evidence and remaining join

[`CommonProtocol` controls](../../../../formal/Tests/CommonProtocol.lean) cover
three roles with different state types, two differently bound calls to one body,
restoration of the parent binding, independent reception, nested invocation
paths, compact loops, ordered tuple binding and failure after local/send/receive
effects. Negative controls distinguish role ownership, result order, wrong
signatures and a different body with the same signature. The fixture also proves
local-effect admission for its actual interpreted local body.

`child_run_eq_direct` equates the source child's **complete execution** to a
separately written sequence of local actions and message delivery for arbitrary
runtime services, inputs, bindings, paths and states. It is not a participant
projection theorem. The controls use natural-number services to expose binding
and state behavior; they establish no cryptographic protocol or performance claim.

The [scheduled participant lowering](../compiler/scheduled-participants.md) now
proves complete execution preservation for this grammar and its actual stored
callees, including fixed loops. Independently callable role-module extraction,
portable symbols/inputs, role instantiation and source-site resolution remain
to connect. Global choice additionally needs actual
agreement/delivery or justified merging of uninformed continuations. The
[agreement check](located-execution.md#actual-agreement-for-shared-control)
does not supply those premises or introduce a consensus protocol. Resource
linearity and construction-specific laws remain admission obligations rather
than consequences of the port types.

*Design context (informative).* Located types and the separation of local
computations from distributed functions follow the issues studied in
[Pirouette](https://www.mpi-sws.org/tr/2021-004.pdf). Production mapping must keep
SSA operands separate from callable symbol references, following
[MLIR symbol and symbol-table interfaces](https://mlir.llvm.org/docs/SymbolsAndSymbolTables/).
These sources motivate the separation; they do not prove this profile's
projection or prescribe its final dialect operations.
