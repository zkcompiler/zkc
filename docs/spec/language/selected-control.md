# Selected source control and common requirements

A checked `if` evaluates its Boolean selector once and checks both arms. A
checked ordinary-enum `match` evaluates its scrutinee once and checks exactly
one arm per declared alternative, in declaration order. Payload binders precede
captures in each closed arm. Only the selected arm executes. Value-producing
control requires a value on every continuing path with the same type and exact
placed identity. Equal types, participation summaries and sorted role sets do
not identify a record's ordered role telescope or its resource roots.

Math arms admit total mathematical work. Local arms retain Scope/Outcome
execution. Protocol arms retain explicit captures, immutable service-root
aliases, participant roster, typed/placed yields and authored sites. Math lowers
to registered `data.branch`/`data.yield`; Protocol lowers to registered
`protocol.branch`/`protocol.yield`. Missing native operations refuse with
`source.control-native-unavailable`. No eager selection or complementary loop
encoding supplies selected semantics.

Protocol `if selector roles(P,V):` and `match value roles(P,V):` use that exact
roster. Omission uses the active roster. A singleton roster admits role-local
nonuniform control; every nested action must remain within it. Shared scheduling
requires common provenance separately from availability. A shared header cannot
be justified by a `public` flag, a name, equal types or a source assertion.

Every arm independently checks moved places, required usage and service owners.
Mutable state survives only where every continuing arm returns its whole
successor. Logical products preserve complete recursive placements. Native
resource-origin analysis independently checks exact recurrence: a new resource
with the same type cannot stand in for an old root. Bounded repetition checks
its initializer, transition and zero-trip result. Branch-only facts do not
escape to zero trips or sibling arms. One participant's completion does not
complete a peer. `finish_if` retains its enclosing Entry completion contract
and statement boundary.

## Derived admission obligations

Signatures, dispatch selection, explicit bounds and repeat maxima retain their

## Facts and retained correspondence

The source fact adapter recognizes the installed index-less-than-extent bridge
at an actual successful guard or selected true path. It associates exact
immutable index/container origins and confines participant facts to their owner
scope. Sibling-arm and loop-body scopes do not export newly reached facts.
The mathematical kernel receives established scoped results, never an
undifferentiated collection of Boolean assumptions. Existing formation
preconditions remain caller obligations.

Independent original comparison checks actual selector/capture operands,
service roots, ordered alternatives, payload arguments, result roles, every
arm body, exact yields and sites. Untaken arms are included. Closure comparison
rechecks arm mode, roster, service associations and complete substitution.
Written source and elaboration retain authored branches. Structured-source
rows and application maps retain explicit arm coordinates, distinct from
source field paths and dynamic iterations. A labelled branch exposes claim
sites as `branch.alternative.event`.
Native ordered sites inside each arm encode the exact containing branch site
and alternative before the local label. Sibling arms can therefore reuse an
authored event label. Claim `native_path` entries preserve application edges
and use this qualified site for the selected event.

This source contract adds no independent formal interpretation or proof.
Executable admission, oracle realization, security transformations and formal
consumers must separately support their selected profiles or refuse explicitly.
