# Original-source validation

Original-source structural validation and mapped Rust admission/scheduling use
explicit-binding `zkc.protocol/1` carriers. The
[local host](../../runtime/inputs.md) supports multiple setups and original
source ports. Independent source execution, constructed artifacts and a bounded
local physical interpreter supply different correspondence checks, described
below. General physical control/view correspondence remains outside that evidence.

## One source, a checked candidate

Independently form the original generic source in Lean. Validate the actual
candidate against it, using candidate bindings, types, operations, sites and
logical origins as untrusted witnesses. Do not reproduce C++ symbol hashing,
code-sharing decisions or physical-plan search in a second compiler.

The same admitted source supplies the executable reference. This combines
independent source meaning, candidate-local validation and differential evidence.
A candidate-origin assertion is not evidence until its body and each call site
are checked against the selected source definition/configuration.

Every source declaration/configuration is formed, including unused ones.
Reachability controls specialization emission. Static consistency includes
known consequences of equality and associated-member congruence; residual
requirements do not imply that a satisfying completion exists.

The requirement proof checker receives assumptions, installed rules and body
goals reconstructed from source. The independent bounded search currently
produces its own derivations and checks every inserted fact through the existing
Lean proof-producing kernel. Its hash index accelerates lookup; retrieved facts
are checked against the requested conclusion. Missing proofs refuse formation.
Compiler-provided derivations remain a possible optional witness. Literal casts
are checked from the original bounded decimal natural and selected field modulus.

## Integration objects

Reuse existing syntax/control and semantic owners:

- `Zkc.Source` owns typed source formation, substitution and interpretation.
  [ResultBundle](../../../formal/Zkc/Source/ResultBundle.lean) embeds ordered
  multi-result operations into the existing region through heterogeneous bundles
  and pure projections. Empty bundles represent unit. Invocation preserves the
  complete procedure and its execution, including a stopped post-state.
  Administrative projections do not become native instructions or imply an
  allocation cost model.
- `Zkc.Compiler` owns semantic relations and validator soundness results.
- `Tools.Interactive` owns bounded portable decoding, independent source formation,
  candidate checking and reference execution. Operation signatures come from
  explicit nominal bindings, not a module-wide cryptographic profile.
- `Tools.Artifact` interprets construction over the same admitted source and a
  checked descriptor, preserving the existing exact-request primitive boundary.
- The admitted Rust object retains original source bytes and checked maps from
  source ports/local occurrences to candidate ports/callables. The host needs
  those maps for scheduling and setup policy; canonical SSA names are not a
  source API.

The candidate normally contains the needed witness. Add a bounded auxiliary
record only when an obligation cannot be reconstructed—for example a requirement
proof or an otherwise unavailable occurrence map. Avoid publishing another
complete monomorphic module solely as a checker input.

Generic source preparation retains typed local regions constructed by
[TypedLocal](../../../formal/Tools/Interactive/TypedLocal.lean). This reifier
resolves the original source's semantic bindings, checks attributes and affinity,
and binds result ports in declaration order. It keeps source function origins and
operation sites. Only source names can refer to the projected SSA bindings; the
internal bundle has no source name. Region typing itself does not enforce affinity.
Semantic requests omit private binding names and implementation choices; the
separately checked physical plan retains those choices. Typed variable references
share their existing paths when contexts grow.
The reifier is executable and tested but has no raw-to-typed adequacy theorem.
The generic checker therefore reports `no-elaboration-adequacy-proof`; its
structural correspondence claim remains distinct.

## Executable source reference

`--generic-reference SOURCE INPUTS` executes the independently formed original
source, without reading a native candidate. `--generic-role SOURCE INPUTS ROLE`
retains only the selected role's inputs and consumes explicitly supplied peer
replies.

[Control](../../../formal/Tools/Interactive/Control.lean) shares common-source
traversal with the portable interactive interpreter: role stores, subprotocol instances, loop
captures/carries and stopping cuts. It is parameterized by values and services,
not by a cryptographic profile. [GenericReference](../../../formal/Tools/Interactive/GenericReference.lean)
supplies full nominal types and runs the retained typed local regions through
`Region.denote` and `PIR.Proc.run`. Instrumentation and detailed faults live in
the handler state; the core handler's event type is empty. This is an executable
connection to the selected denotation, not an elaborator-correctness theorem.

Field and polynomial arithmetic use the independent Lean mathematical operations.
RNG tapes and nonce records model deterministic test services, including consuming
attempts, generation, remaining budget, nonce stages and untouched resources. Real G1
operations require an external reply keyed by the entire semantic request:
dynamic source location, logical definition/static identities, operation,
attributes and operands. Missing answers produce `pending-primitive`; an answer
for another site cannot fill the request. Wire-structure checks are independent;
subgroup validation and group equations remain provider assumptions. Reply keys
are indexed after canonical serialization; duplicate records refuse admission.

The current native comparison checks full source operation request/response logs,
ordered sent/decoded messages, return values, failure locations and RNG state.
Native stops identify the enclosing local invocation; the finer source operation
is additionally checked against the observed failing primitive request. Before
normalizing a native path, the observer checks its format and intermediate call
instances against original source dependencies and loop bounds. It includes mixed table layouts,
shared and distinct instances, Boolean operations, nested calls/loops and later
iteration failures. Real native relayouts execute and are counted; only their
successful administrative steps are omitted from the logical comparison. Native
frame cleanup and immutable inputs are checked separately. This logical corpus
does not establish physical accounting; the separate local interpretation below
supplies bounded evidence. PCS reference services compare immutable original
custody, independent polynomial evaluations and conditional commitment/proof
services; unsupported requests are never silently evaluated by a fake profile.

The installed polynomial contract checks matching operand ranks before positive rank
for product rounds, positive rank for folding, and exact point rank for evaluation.
Violations report `arity-mismatch` or `positive-arity-required`. These checks are separate from mathematical helper diagnostics. Common loops advance incrementally;
unused iteration bounds do not allocate an iteration list. Host session identifiers
have a separate 1–128-byte ASCII alphanumeric/`_`/`.`/`-` domain, including at the
first character; source-symbol rules are not reused for this host field.
Transcript attributes use five labels with that same bounded alphabet, checked
at source formation as well as runtime admission.

Joint observations explicitly name `tools-joint-schedule/1`: sender transfer
precedes receiver polling, and final draining follows lexical role order. The
separate runtime cut driver has different polling behavior and is not covered by
that joint observation. Reference work/stack limits remain interpreter limits.

Logical resource admission also applies to unchanged values crossing child and
local boundaries. Joint traversal records the first boundary failure per role
until the native schedule next polls that role, preserving other roles' preceding
actions. This independently checks domain/generation/alias conditions; physical
frame membership is not inferred from logical operands.

### Stateful service boundary

The reference services separate state owned by the interpreter
from mathematical answers supplied externally. Extending `external` to accept
opaque successor handles would not establish that a service consumed the right
resource or retained the right subject.

- PCS opening state retains the selected setup identity, exact immutable logical
  table and issued commitment. The reference computes an opening's scalar value
  from that table; commitment/proof bytes and the verification equation remain
  explicit provider answers. Independently checked wire shape and setup policy
  must not be inferred from those answers. Distinct authorized setups and repeated
  borrowed openings are required controls.
- Implemented nonce state records issuance, commitment and spending separately from its
  generation and budget. Native consumption advances counters before budget
  refusal, but checks/transitions nonce stage only after budget succeeds. A stage
  failure pessimistically spends the nonce. The reference must preserve that
  order; group answers cannot restore consumed state. The interpreter constructs
  successors and computes scalar responses. A group service request binds the
  actual bases and issued scalar, with independently checked result shape.
  Deterministic test secrets belong to the issued service fixture and private
  development service requests, not production protocol observations.
- Implemented transcript state records the issued root and ordered absorbed data.
  A hash/challenge service key must bind that history as well as the current
  request. The current location and numeric generation alone do not identify
  transcript contents across executions. Native hash implementation choices stay
  in the selected service contract, not a global arithmetic profile. The provider
  supplies only 64 hash bytes; the reference independently encodes origins/wire,
  owns consuming history updates, specifies the full Merlin domain/label/call
  sequence, and reduces those bytes into the field. The external adapter
  interprets the explicit request program.
  Construction correspondence and Fiat–Shamir security are separate obligations.

The [PCS implementation](../../../formal/Tools/Interactive/ReferenceCommitment.lean)
constructs immutable custody and rejects opaque provider-supplied state. Its
[setup context](../../../formal/Tools/Interactive/ReferenceSetups.lean) separates
role authorization from exact intended receiving-key selection. Actual two-setup
messages exercise successful and refused selections, including equal-rank keys.
The
[resource implementation](../../../formal/Tools/Interactive/ReferenceResources.lean)
covers RNG and nonce transitions; the
[transcript implementation](../../../formal/Tools/Interactive/ReferenceTranscript.lean)
uses the same consuming state. The underlying typed region and process carriers
need no extra protocol-specific constructors. Frame views, storage retention and
allocation failure still belong to the separate physical interpretation below.

## Initial physical relation

The first validator supports fixed callable boundary representations and exact,
local operation selections. At an operand crossing, it permits the required
conversion from the current representation to the selected kernel port. At a
return crossing, it permits the required conversion to the callable result port.
Conversion endpoints, field identities, aliases and SSA positions are checked.
No arbitrary extra conversions, cancellation of inverse conversions or movement
across earlier source operations is admitted by this initial relation.

A logical process alone does not specify native allocation failure. Separate:

1. Static instantiation preserves the selected source process.
2. A physical realization implements that process under explicit execution
   limits, primitive contracts and representation-transition obligations.

The realization model describes allocations, retained outputs, instruction
charges and failure positions independently of candidate execution. Its inputs
are the checked source operations, selected representations and resource policy.
It must not define correctness as agreement with whichever candidate was given.

Unconditional equality under arbitrary identical budgets is not claimed. Added
conversions consume resources. Success correspondence requires their resource
premises; failure correspondence retains the exact completed prefix, resource
successors, untouched resources and frame cleanup. A valid adapter cannot add an
arbitrary abort merely because the logical process has not produced a value yet.

Reference observations therefore distinguish logical events, implementation
steps, authority/ownership, generation, cursor/budget, nonce stage, active views,
retained storage and terminal outcomes. A matched value list is insufficient.
External PCS scratch is currently bounded by rank, not reserved in the runner's
output-payload budget; this remains an explicit backend contract boundary.

The first physical interpreter and comparison implements the
single-root/local-call/return scope after whole-source checking. It retains
input storage capacity as host metadata, uses checked representation crossings
and applies mathematical source operations. Fresh exact-capacity allocation is
an explicit premise checked on the native results, not an allocator theorem.
View counts are observed; general frame membership and nested-control resource
correspondence are not claimed.

## Bounded delivery and assurance

The installed vocabulary supports generic local bodies with multiple results,
acyclic helper calls, partial immutable configurations, shared closed code,
both table layouts, multiple setups, and protocol calls/loops/stops.
[Local composition](../local-composition.md) states the helper expansion policy
and its independent reference checks; local control and physical resource
correspondence each retain their documented bounds.

The source-driven interactive and constructed hosts must consume the same checked
maps. Construction selects the semantic instance first and interprets the
supported construction relative to it. No universal commutation theorem between
arbitrary construction and specialization is assumed.

The implemented structural checker supports generic instances and explicitly
bound local functions through one body relation. Callable names without an
explicit logical origin remain part of their identity. Generic aliases can share
a candidate function; unconstrained instances can admit more than one physical
selection. The returned host map records the actual selection at each
`(instance, role, local site)`, rather than the set of all compatible functions.
Rust independently checks map coverage and target coordinates against its typed
program before retaining source and candidate bytes in immutable custody.

The portable environment resolves explicit operation bindings through the common
control checker. It does not assign a synthetic global profile. The portable
checking claim is executable source-relative structural validation with tested
conformance. The typed
requirement/substitution theorems have their separately stated scope. In
particular, typed substitution preservation does not certify the executable raw
source specializer; `ResultBundle` governs the denotation actually used after
reification. A theorem
connecting raw admission, the complete validator and actual native execution is
not implied by enabling the checked path. Backend cryptographic correctness,
host setup authentication and Fiat–Shamir security remain separate obligations.

For G1/PCS/transcript primitives without independent implementations, use explicit
primitive laws or exact-request providers. The additive reference group cannot
stand in for actual G1. Differential tests must identify which arithmetic is
independently computed and which responses are under an external contract.

## Acceptance

Cover original-source mutations and candidate mutations separately: unused bad
declarations, partial contradictions, altered static arguments/literals, forged
origins, shared calls, wrong ports/nominal domains, misplaced conversions and
extra allocation attempts. Include positive, rejected, exhausted and pending
executions, nested calls/loops, resource aliasing and failures after consumption.
