# Architecture of source-issued security claims

A security claim needs two kinds of evidence. The first identifies the program, role, stage, view and local functions denoted by the source. The second proves a property of their executions. A kernel-checked proof can establish exactly the wrong claim if the compiler chooses a different protocol specialization before Lean sees the target. The architecture should make that first choice inspectable and test it independently.

## Boundaries in the current implementation

| Owner | What it determines | Evidence at the boundary |
| --- | --- | --- |
| Source frontend | The selected entry scheme, closed protocol instance, defining contract, public operands, event fields and the functions selected by the clause | Ordinary name and static resolution, ordinary body elaboration, source locations and checks against emitted ports and addresses |
| Core | The well-typed program admitted from the stored form, the projection for each role and its process semantics | Three readbacks for the group fork. They connect the actual protocol, relation and extractor to their respective admissions |
| Formal semantics | What an execution, a fork, an observation or a probability means | Exact returning transcripts, stateful effects and finite expectation all refer to the same Core process. The bind theorem for process interpretation supplies their structural composition |
| Family mathematics | Why the observed equations imply the requested property | One group-action extraction lemma covers the two group examples. A shared reduction theorem covers the pair and gate rounds with different collision laws |
| Proof automation and companions | How to construct evidence for a target fixed by the preceding layers | The group strategy walks the projection and checks the calculation against both local function meanings. A companion can use the compiled target directly |

Source parsing, static resolution, elaboration and lowering are trusted compiler operations. Admission and readback relate stored Core to its typed meaning. The independent consumer applies the public theorem to three successful admissions and requests a fork over the actual role and function executions. The consumer supplies its own argument order, source-named projections and three event addresses. It rejects both a theorem of `True` and a valid special-soundness theorem whose three operands consistently exchange the base and the public point. Kernel replay checks the logical declarations in the two baseline modules and their project import closures. ## Which duplication to remove

**Represent the author's inputs once.** For a supported group protocol, the extractor sees a sized sequence of generated `Run` records. Its nominal identity belongs to the closed protocol instance. Source typing owns collection length, indexing and field projection. The record stores a field for each of the three public events in their source order. An unnamed event uses its ordinal selector. A local binder may have a different name from its site. Import-fixed specialization, public context and role designation belong to this boundary too. A `G2` run cannot justify extraction for a `G1` scheme. [Generated members](../language/LANGUAGE.md#8-generated-members) · [Contract binding](../lean/compiler/Zkc/Frontend/Written/Contract.lean)

**Share the instruction rule at the level where it is valid.** A guard private to the prover disappears from the verifier projection. A shared guard constrains every accepting verifier execution. Exact traces and stateful probabilities can share structural recursion and bind. They need different effect rules and return observations. For example, finite expectation uses each reply's weight and threads the service state. Its monotonicity theorem only needs an inequality on returns reachable with positive weight. A single Boolean acceptance check would lose that distinction. [Projection rules](../lean/formal/Zkc/Formal/Written/Steps.lean) · [Process interpretation](../lean/formal/Zkc/Formal/ProcessJudgment.lean) · [Finite expectation](../lean/formal/Zkc/Formal/Interactive/Experiment.lean)

Clients can rewrite expectations with `expect_bind`, `expect_done`, `expect_halt` and `expect_call`. These equations keep a proof about the experiment independent of how the shared interpreter recurses.

**Keep two representations when their agreement is the evidence.** Stored and typed Core have different consumers. Readback checks their correspondence. The short relation and extractor calculations are optional inputs to the automatic group proof. Both must agree with the admitted local functions on every input, including a failing division. The public result and the companion entry point use the compiled executions. A second translation with no such agreement would introduce a second source of truth. [Generated declarations](../lean/compiler/Zkc/Frontend/Written/Export.lean) · [Function interpretation](../lean/formal/Zkc/Formal/Written/FunctionMeaning.lean)

**Quantify laws over the operations a theorem uses.** For a reduction of length `n`, the round theorem accepts a polynomial interpretation at each remaining depth in `Fin n`. Its root bound uses just that depth and its predecessor. There is a concrete four-round claim with a valid polynomial at every executed round and inconsistent requirements at the next depth. Requiring those extra laws would exclude this instance without improving the bound. At a world read, the owner operation has the actual listener list, so its grant must match this list. The recorded owner event has already erased the list and admits an existential statement about the original grant. [Reduction theorem](../lean/formal/Zkc/Formal/Interactive/RoundFamily.lean) · [Four-round control](../lean/formal/Zkc/Tests/Formal/Interactive.lean) · [World observations](../lean/formal/Zkc/Formal/WorldObservation.lean)

The round interpretation has one representation for both kinds of client. A Sumcheck proof can supply its formula at every natural depth. A GKR proof can supply a polynomial for each of its four depths. Restricting the first proof to the executed indices or passing the remaining indices to a recursive call preserves the same boundary function, evaluation and collision proof. [Sumcheck interpretation](../lean/formal/Zkc/Formal/Interactive/PairSequence.lean) · [Gate interpretation](../lean/formal/Zkc/Formal/Interactive/GateSequence.lean)

The [joint language design](source-elaboration.md) records the implemented contract and goal representation, the shared property vocabulary, the returning-record check, and the research behind the remaining work. Each package below owns its source rule, instance elaboration, Core meaning and independent evidence together.

## Installing a Sumcheck round from another source module

The [mixed client](../examples/mixed_rounds.zkc) imports both the original endpoint round and an [external coefficient round](../examples/support/rounds/coefficients.zkc). Both send a pair of field elements. For a received pair `(2,3)`, the first round describes the line from 2 to 3. The second describes the polynomial `2 + 3X`, whose other endpoint is 5. At challenge 1 their answers differ. Swapping the modules leaves the two-round client's total charge at four field challenges. Neither the wire type nor the charge identifies the polynomial.

1. The client explicitly supplies a compiled companion. The [source reader](../lean/formal/Zkc/Tools/Formal/RoundSpecification.lean) follows the reduction's selected module and checks its typed `ends` and `at_point` laws, field, two executable member instances and degree-one external line. It reads projections and sums in the endpoint expressions. Other polynomial languages can supply a different proof path.
2. The [installer](../lean/formal/Zkc/Tools/Formal/InstalledRound.lean) checks those two functions in the admitted callee's own table once per installation. Every executed block must call those exact operations. The coefficient companion also recognizes an evaluator that forwards to one earlier helper, checks both forwarded operands and proves that helper's law in the wrapper's table. An empty reduction has no executed members to certify. [Executable companion](../lean/formal/Zkc/Formal/Interactive/CoefficientMembers.lean) · [Polynomial equations](../lean/formal/Zkc/Formal/Written/CoefficientPolynomial.lean)
3. The family proof uses the decoded endpoints, the true remaining cube and a fresh challenge. Disagreement at the boundary leaves at most one collision for a line. At a caller, the [application rule](../lean/formal/Zkc/Formal/Interactive/MappedReduction.lean) retains its actual operand holders, role map, frame and service state. To use its local bound, the caller establishes the entry operands and shows that its observed return implies a correct residual. The degree-two Gate proof continues to use its own primitive and polynomial laws.
4. For one table-sum call, [the written goal consumer](../lean/formal/Zkc/Tools/Formal/SingleRoundGoal.lean) also checks the root verifier, relation arguments, terminal guard and the named goal's whole table of paid locations. `primeBound` bounds acceptance of a false public sum on the admitted verifier under a fresh uniform BLS12-381 scalar challenge. `degreeOneTotal` gives the written ceiling `n / |Fr|` when the source fee is one over the field order. A mixed client currently obtains an installed witness at each call and its source cap table. A security theorem for the entire mixed verifier needs a proof for its continuation.

Run `just test-interactive` for independent compiled layouts, equivalent and faulty helpers, source-only specification changes, altered guards, reversed roles and a nonempty prefix. Run `just test-packages` to compare the mixed client's kernel-elaborated package with the frontend output. General written reduction predicates, oracle services and transformed verifiers have separate obligations.

## Target design and delivery plan

The deliverable is a theorem that another Lean module can apply to the executions selected by a source declaration. For example, the written Chaum–Pedersen knowledge clause asks whether the *compiled extractor*, on two accepting verifier executions with the same commitments and distinct challenges, returns a scalar satisfying the *compiled relation* for both public bases. Its random-oracle knowledge goal asks a different question about a different program and model. The current group exporter proves the first claim. A new property or protocol should reuse the route from the named declaration to its executions and acquire new mathematics only for the verification conditions that remain. [Example and goals](../examples/chaum_pedersen.zkc) · [Current coverage](status.md)

### The subject of a proof

1. Ordinary elaboration resolves the closed protocol, roles and port names. From its typed body it derives the nominal schemas for the author's views. For a scheme it keeps the scheme context separately from the protocol instance. A typed clause retains the ordered source expressions, event parts, scope, relation and any function selected by `by`. A goal selects a property, the scheme, stage, model, arguments and required clauses. Two schemes may share a protocol instance and have different goals. Generate header-dependent members first, then body-dependent members, wake waiting definitions, and diagnose a cycle with the participating source spans.
2. Export the stored programs, their admissions and a correspondence for each required operand and event of the selected subject. For each slot, evaluate the **named expression** in the source environment and relate it to the value passed to the actual entry. Include the projection and the relation and extractor argument lists. Check source-level view field names, types, order, presence and access against the admitted event schema. An independent consumer must construct its expected packing from the named fields. If both sides use the exporter's packing function, even a simultaneous exchange of two same-typed arguments can pass. Ordinary elaboration and lowering remain trusted for identifying the source declarations.
3. A Lean library property specifies its required subjects and defines a proposition over their executions. Existing forms such as `knowledge … by extract` may keep their surface syntax and elaborate to the same typed property application as a new library property. The library defines special soundness, challenge multiplicities and the mathematical obligations those multiplicities entail. The frontend checks names, declared argument kinds, visibility, stage and supported fork shapes. A companion imports the issued subject and proves that proposition, including any missing representation law or invariant. This gives authors ordinary Lean for new property definitions. Source needs a language change when a property requires new *source evidence*, such as a previously inexpressible event part. A new theorem over already exposed evidence needs only a library declaration and its binding. Keep the clause-oriented entry point alongside named goal selection. Report the selected clauses, uncovered clauses and assumptions. An unavailable requirement of the selected goal prevents issuing that goal.
4. Package the correspondence and the property proof for the **same** admitted subjects. A consumer should be able to inspect them separately. In a written fork two extra context fields can be projected away if all three executions factor through that projection. In a constructed signature the actual transcript calls must consume the specified ordered and delimited bytes. The stage determines which correspondence theorem is needed.

### One account of observations, with explicit visibility

Core owns event identity, typed effect arguments and replies, role projections and process semantics. Give each declared event part a typed mapping to its realizations in the closed program and each runtime occurrence a path. A realization includes the selected callee, role mapping, captures and result type where applicable. Use that mapping for layout, clause attachment, charging and field access. A charge refers to a declared part and its stated multiplicity. Its proof accounts for the reached occurrences. For round families, reuse one body indexed by the actual changing parameters, with an interpretation at the remaining depth of each call. Share physical keys or emit a uniform loop only when full-location lookup and type-correct reconstruction agree for every occurrence. A uniform-law adapter still serves uniform families.

The common semantic input for observations is a typed event *with* its payload, principal, audience, reply and occurrence. Define the correspondence from an execution to each authorized view. Keep different execution relations for joint honest runs, open role processes against a strategy, and probabilistic experiments. A joint witness can justify a role trace under its specified service and projection. Reconstructing a joint execution from arbitrary local traces requires a realization theorem and compatible strategies.

| Consumer | Evidence available | Example that distinguishes it |
| --- | --- | --- |
| Extractor's written `Run` | The stage-specific record prescribed by the protocol, including ideal oracle data where the language grants it | Two hidden tables can produce the same opened row and different extractor records |
| `Received<R>` and `Coins<R>` | The fields received by the named role and its own coins under the respective language rules | A listener hears a service reply. The owner supplies its arguments. A private sample can be a coin without a field in the extractor record |
| Service and quantitative proofs | The authorized call, actual payload and state transition. Record the result, halt or unavailable reply required by the property | Two calls with the same reply may store different tables. Missing mass cannot be recovered by conditioning on successful replies |
| Fork or simulation | A relation over the specified views and executions | A two-branch fork requires the shared prefix at its chosen draw and distinct challenge values. A one-run extractor needs no rewind. A simulator is compared on the declared observer's distribution |

Derive the applicable record from this evidence and check it against the frontend schema after admission. Core already has a shape-indexed record on returning executions. Preserve its optional branches, repeated fields and nested application structure. Give stopped prefixes and private observations their own semantics. Begin with the straight-line group programs. The current language restricts draw positions for sized fork trees. A two-draw tree with multiplicities (2, 3) and one with (3, 2) both have six leaves under the source array representation. Before issuing a multi-draw property, carry the ordered draw origins, laws and multiplicities into the contract operand and prove shared-prefix alignment at each draw. The one-draw group certificate fixes its single draw and both branches. ### Construction of a proof

Share the induction over the admitted program or projected process. Give each typed operation a rule for its environment, continuations and effects. Returns, program stops and failure to receive a reply have the meanings of the particular judgment. Use exact returning trace rules for verifier equations, total-success conditions for extractors, and expectation or budget rules for reached challenge events. Specialize the shared bind theorem to each. Use Lean's verification-condition generator where rule selection is predictable. A typed traversal can select a rule directly for dependent instructions. Either route produces kernel-checked terms against the same target. Local function calls compose their admitted summaries. Loops, branches and retries require scoped invariants and a rule for the actual stopping condition. A failed tactic must still leave a usable companion target. [Process interpreter](../lean/formal/Zkc/Formal/ProcessJudgment.lean) · [Lean verification-condition generation](https://lean-lang.org/doc/tutorials/latest/vcgen/)

The verifier walk yields the guards on returning paths. The local-function walk supplies success and failure conditions for the extractor and relation. Only then apply the family mathematics. A group fork has one difference lemma per verification coordinate and one common witness. Orient each equality locally. Exchanging both run indices preserves the extractor, while exchanging just the numerator can break it. For Sumcheck and a GKR reduction, share round composition at the actual call depth. Derive the collision bound for degree at most `d` from polynomial roots on distinct sampling points. The family must identify the polynomials and show their disagreement in the reached state. A whole GKR proof also needs its caller's wiring, line reduction, layer composition and terminal evaluation. A new family may discharge its residual obligations with a Mathlib lemma, an ArkLib or VCVio theorem with matching semantics, or a companion. Importing a whole protocol result requires agreement on initialization, strategies, observations, success events and losses.

### Executable models and probability

Keep Core and the compiler independent of the mathematics libraries. Audit their designated roots transitively with `propext` and `Quot.sound` permitted. Adopt one policy for the formal package, including interactive proofs, which also permits `Classical.choice`. Pin Mathlib and VCVio to compatible immutable revisions and audit the declarations reachable from each published theorem. List mathematical premises, model assumptions and compiler trust separately from foundational axioms. Require actual axiom reports, successful imports and kernel checking.

Build the formal model from mathematical carriers and operations. Index the interpretation by the resolved row and its signature. Derive the verifier, extractor and interactive interfaces from that interpretation. For the first group model supply a field, an additive group and its scalar action, plus the representation, literals and equality used by the emitted Core vocabulary. Restricted scalars need a refinement preserving validity, nonzero decoding for valid inputs, forgetting, and the inverse laws on that domain. Keep explicit coverage of supported rows, including reachable callees. A total model may need interpretations of unused rows; default values there give no cryptographic laws for those rows. Test a group of odd characteristic as well as the existing two-element model. A separate cross-model theorem must justify any claim about a concrete runtime encoding. Pairings later exercise two source groups, a target group and the pairing law.

State public quantitative results in VCVio's event probability. The frontend evaluates a closed ceiling using exact rational arithmetic at the selected instance. The source certificate retains the equality between this state's emission at the selected root and the program submitted for admission. It resolves all occurrences of the named draw, checks the ordered addresses against the admitted verifier, and compares the written ceiling with the degree divided by the actual alphabet size. A weaker ceiling is valid. Zero-trip loops retain their source event and contribute zero. Sumcheck checks the resolved public sum relation and the extension of its actual table. GKR checks the summand operands and gate members of the same call. Both use Mathlib's root count on the difference of bounded-degree polynomials. Transferring the resulting finite-process bound to a VCVio event only needs its count and ceiling. Independent fixed-table samples instead compose multiplicatively by VCVio's product measure. [Issuance](../lean/formal/Zkc/Tools/Formal/DrawCharge.lean) · [Round bounds](../lean/formal/Zkc/Formal/Written/RoundCharge.lean)

Thaler’s round argument applies after receipt of a message and a successful boundary check. A fresh uniform challenge hits at most as many roots as the degree. Summing conditional bounds permits adaptive prover messages. The proof uses the existing correspondence with the emitted role process and supplies exactly that process to VCVio. A finite-slot service samples a new index and returns both a reply and a successor state. The bridge counts duplicate replies by multiplicity and assigns unavailable replies and stops zero returning mass. In the Sumcheck example, Mathlib checks the primality of the source field order and interprets all used table and scalar operations over `ZMod`. Issuance handles the field width symbolically. A cumulative-interval adapter remains an option for general rational strategies. [Thaler, chapter 4](https://people.cs.georgetown.edu/jthaler/ProofsArgsAndZK.pdf) · [Process interpretation](../lean/formal/Zkc/Formal/FiniteService.lean) · [Prime-field interpretation](../lean/formal/Zkc/Formal/Written/PrimeFieldCharge.lean)

### Delivery and retirement criteria

| Work package | Deliverable and dependency | Acceptance evidence and what it replaces |
| --- | --- | --- |
| Source binding and views | Start with ordinary elaboration and a source-oriented independent consumer. Bind closed views, clauses and named goals to the emitted roots. Derive the group run and authorized observations from the admitted events. | Both written group claims still apply to all three admissions. Reject a consistent same-typed slot exchange, wrong role, wrong specialization and unavailable selected stage. Resolve two labelled clauses, additional context and reordered declaration lookup. Check named stage-specific coverage. Retire exporter-only member injection and the duplicate contract scan for supported subjects. |
| Formal libraries and a model | Start in parallel with source binding. Establish clean package imports and axiom audits, pin dependencies, then construct the arithmetic model with the rows required by the first consumers. | Derive the existing four group interfaces and exhibit accepting distinct forks in an odd-characteristic model. Reject a one-sign mutation and zero-as-valid-nonzero. Exhibit a returning challenge. Exercise used sequence and polynomial rows for the reduction. Retire duplicate row laws as each consumer switches. Recover the historical model construction and cross-model specification before retiring obsolete imports. |
| Common proofs on emitted programs | Bring binding and the model together. Replace the optional calculation renderer with typed rules. The emitted Sumcheck verifier and the GKR reduction now have VCVio bounds using an answering uniform service. | Both group proofs use the same library strategy with individually reversed guards, run exchange, a local alias, a length guard and an undefined inverse. The one-sign and false-guard controls must still fail. Close one round first, then compose emitted Sumcheck and the GKR reduction with position-specific laws. Exchange two different callees as a negative control. Keep the dependent admission witnesses in public theorems. Retire shape-specific walks and hand-counted degree-one/two lemmas when the source clients pass. |
| Stateful written oracle | Use the same subject, event schema and external probability for an independent family. Elaborate the actual spot-check source. Fix the ideal table at send and retain a scoped handle. The opener supplies the queried rows. The service checks the claims against the saved table and positions at opening. | A real honest run returns. Every live handle preserves its snapshot. Distinguishable handles, wrong queried rows, private reads and forged audiences have negative controls. Tables differing only at an unqueried row may look identical to the reader. Prove the written bound with an explicit distance threshold and sampling policy. Reusing a single draw must invalidate a claimed independent repetition bound. Retire the handwritten reader once joint and projected evidence agree. |
| Transformed programs and richer games | First execute one actual Schnorr Fiat–Shamir stage. Bind its transcript bytes, domain, arguments, order and service state. Then prove the reduction for the stated adversary, query limit, retries and aborts. | Byte-order and boundary mutations, consistent repeat queries and the actual constructed verifier are checked. A simulation goal separately requires real and simulated experiments with the specified views. A setup can enter as public parameters with explicit assumptions. Claims about setup secrecy require a setup experiment. Several online honest roles require authorized joint scheduling or a commutation proof. Commitment refinement, whole GKR, concrete runtime correspondence and recursion have their own premises. |

For one honest role, constrain the opponent through the typed handler interface and its observable state. A private draw cannot reach the opponent through an absent input. Where parties can invoke a shared service, bind the principal and handle to the operation. When claiming that a grant follows from source, prove that the admitted projection respects the declared audience. An arbitrary table of grants or a fixed-source joint run cannot establish security against every strategy.

Evaluate generality by adding a property over existing views, a protocol from a different family and an equivalent rewrite of an existing protocol. Record which frontend definitions, structural rules and mathematical lemmas each change required. Benchmark emitted bytes, proof terms or verification conditions, checking time and peak memory across increasing source sizes under repeated comparable runs. Preserve independent consumers and controls while retiring old paths. Run the compiler, interactive and written gates for cross-layer changes, the default formal import/build for the new package boundary, and the public-tree checks for documentation.
