## Package and model

A written soundness goal carries its scheme's protocol, the instantiated deciding clause and its numerical fields. A deciding clause holds a short application of its relation (the relation, the split of its parameters, its Boolean result and the typed positions of its statement operands in the full deployed input header), its place in the contract and its witness operands. A statement is rejected when no valid relation witness makes the relation return true; a witness at which the relation stops does not accept it. The public claim uses the same verifier inputs for rejection and execution. Source names enter when the module presents these binders to an author. The receipt, admission lookup and fees judgment all use the same resolved goal. [Subject data](../compiler/Zkc/Subject/WrittenGoal.lean) · [Formal definitions](ZkcFormal/Written/Goal.lean) · [Public binders](ZkcFormal/Written/GoalPresentation.lean)

For a short application `a` and a chosen probability bound `ε`, `Soundness.Installed M a draws ε` bounds the return probability of the installed verifier on rejected statements. `Soundness.installed_iff_admitted` transfers the bound in either direction at the two looked-up members. `Soundness.Result` pairs coverage with the admitted bound. `Soundness.Witnessed` records a served model and a rejected input. A model is served when some conforming service with a state answers every effect that has a sampler as the sampler draws; the service that never answers conforms, and serves no model in which an effect has a sampler. It is independent of ε. An import test pins the modules of `ZkcFormal` and `Zkc.Subject` that these definitions reach; the judgment with fees and the table of caps are outside that list, and the extraction support that `Source` imports is in it. A judgment by fees at a short application has its own budget and a table of caps that bounds each fee (`Fees.JudgedWithin`); it gives the installed bound at every number that is at least the budget (`Fees.installed_of_judged`), and with the coverage fact the result (`Soundness.result_of_installed`). A goal's bound is spelled as a probability by `Bound.limit`. The published family of a goal still states its judgment at the table's own budget (`Goal.Judged`, `Goal.claim_of_judged`). Written soundness claims use `ZkcFormal.Written.StandardInterpretation`. The library supplies the source scalar field, its additive group, their model, the law samplers and the field cardinality theorem. Goal coverage checks the carriers, rows and laws reached from the protocol and its relation. A proof can use a family lemma through the generic readbacks and specialize it for publication.

To replay a saved challenge, keep its issued statement module, toolchain and dependency versions with the export. The comparator checks the definitions used by its targets. Regenerating the same mathematical proposition with a newer issuer can change those definitions. To use the newer issuer, generate the challenge and compile the proof against its statement module.

Run `lake build` and `lake test` from this directory to build the public formal library and its controls, then replay and audit them. The formal library imports the compiler package’s core, vocabulary and subject libraries. The subject library owns the charge tables and their generic totals. `ZkcFormal.Written.SiteCaps` interprets those tables as allowances, nonnegative rational budgets and probability bounds. Tools and tests can import the frontend to issue statements from source. The formal audit checks this boundary for ordinary and meta imports. This package pins Mathlib and VCVio in its Lake configuration and manifest. Local proof replay uses the built Lean and pinned library modules, traverses proof dependencies for axioms, and accepts `propext`, `Quot.sound`, and `Classical.choice`. The compiler audit uses its original two-axiom policy.

The arithmetic interpretation supplies a field, an additive commutative group and its scalar action. Its nonzero scalar carrier includes a proof that the decoded value is nonzero. Its total model of the vocabulary assigns defaults to other rows. A consumer relies only on the row equations it proves for its operations. The characteristic-five example exercises the literals and operations used by the fork. A nonzero source literal divisible by five cannot preserve both its scalar residue and nonzero validity in this model. The refined literal has a valid fallback value in that case. A faithful interpretation of all source literals requires a compatible characteristic. The formal process comparison transfers predicates on supported executions across two interpretations when the operations match and every allowed concrete reply has a corresponding abstract reply.

For a repeated written charge, compile an assembly with `Written.admitSource` and pass its result to `chargeSumcheck` with the round count and source draw name. The resulting certificate exposes `primeBound` on the admitted root under the BLS12-381 scalar field interpretation. The service can update strategy state after every fresh uniform reply. The GKR component uses the same source lookup, address check and probability bridge at its selected layer call, with a certificate for the executed gate members and explicit model and polynomial hypotheses. Direct named draws accept closed rational arithmetic over literals and static size terms, including powers with an integer exponent. Applications and attempts need their own occurrence selection. The fixed-table check resolves the positions clause of the spot-check example with its extractor marked executable and separately proves the independent-sampling bound in VCVio. Issuing that bound on an admitted oracle verifier still requires oracle send and opening semantics. Run `just test-written-charge` for examples and mutation controls.
