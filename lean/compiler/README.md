# Compiler

The compiler package `zkc_compiler` has no external Lake dependencies. Its default targets build
the Core, standard vocabulary, their tests and the audit. Run `just test-frontend` at the repository root for the whole frontend
build and its driver. `just test-interactive` checks selected source entries through emission,
admission and their formal certificates. See [compiler status](../../docs/status.md).

Libraries:

- `ZkcCore` (`Zkc.Core`): the core language, its admission and its theorems
  ([guide](Zkc/Core/README.md)).
- `ZkcVocabulary` (`Zkc.Vocabulary`): the standard vocabulary of the core, its keys and its
  table ([guide](Zkc/Vocabulary/README.md)).
- `ZkcCoreTests` (`Zkc.Tests.Core`): the checks of the core, which the kernel runs when they are
  built; the test driver of the package.
- `ZkcVocabularyTests` (`Zkc.Tests.Vocabulary`): the checks of the vocabulary's table against
  the reference and the conformance cases that a function over the vocabulary expresses, which
  the kernel runs when they are built.
- `ZkcKernel` (`Zkc.Kernel`): kernel-computation commands used by printed packages.
- `ZkcAudit` (`Zkc.Tools.Audit`): the audit of the declarations and the imports of a library,
  with the replay of its declarations through the kernel.
- `ZkcFrontend`, `ZkcFrontendTools`, `ZkcFrontendTests` (`Zkc.Frontend`, `Zkc.Tools.Frontend`,
  `Zkc.Tests.Frontend`): the lexer, the parser, the checker and the emitter of the source
  language ([guide](Zkc/Frontend/README.md)), the code of its executables and its tests; outside
  the default build.

Executables:

- `zkc-knowledge`: exports the written knowledge claim of an admitted protocol.
- `zkc-audit`: exactly one library target for each compiler module and the audit of `ZkcCore`, `ZkcVocabulary`, `ZkcCoreTests` and
  `ZkcVocabularyTests`.
- `zkc-syntax`, `zkc-check`, `zkc-frontend-tests`: the frontend's lexer, parser and canonical
  printer on source files, its checks, and its test driver; outside the default build.

## Build, test and audit

The entry points of the repository are `just build`, `just test` (the build, the tests and the
audit), `just audit` and `just check`. In this directory:

```sh
lake build              # the core, the vocabulary, their tests and the audit
lake test               # the tests of the core, and those of the vocabulary that they need
lake exe zkc-audit      # compiler library coverage, then the core, vocabulary and test audits
```

`zkc-audit` compares the files under `Zkc/` with Lake's module list for every compiler library.
It imports the core, the vocabulary and the tests of each from their built files and
checks, for every declaration, that its axioms are among `propext` and `Quot.sound` and that it
carries no `@[extern]` or unrecognized `@[implemented_by]`. Lean's recursive implementations
retain their exception; the constructor-index replacements generated by Lean 4.36 are accepted
only when their logical and native bodies match the pinned compiler's construction exactly.
These native implementations rely on the compiler/runtime, not a proof of native execution. It replays the declarations of the four libraries
through the kernel, together with every module that they import outside Lean's libraries, on an
environment that takes only Lean's libraries as built, so that a declaration stored without the
kernel's check is refused. It checks that a module of the core imports only the core, `Init` and
`Std`, and a module of the vocabulary only the vocabulary, the core, `Init` and `Std`; that no
module of the two imports a module of the tests or of the tools; that every file of the two is
imported by its root module (`Zkc/Core.lean`, `Zkc/Vocabulary.lean`); and that every file of the
tests is built and audited. It prints each library's `partial` definitions, recursive native
implementations and recognized constructor indices, what it replayed and what it took as built.
It exits with 0 only when the libraries pass, the generated-helper positive control passes and
all 16 negative controls are refused by their intended rules. These include private attributes
and counterfeit constructor-index bodies/targets. The build also checks ten isolated mutations
of a recognized helper. See the [toolchain guide](../../docs/lean-toolchain.md) for the upgrade's
trust boundary and feature choices.

## Files

- `scripts/generate_unicode_tables.py`: writes `Zkc/Frontend/Syntax/UnicodeData.lean` from the
  Unicode data pinned in `unicode/`; with `--check`, which `just check` runs, it refuses a
  table that differs.
