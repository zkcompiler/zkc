# Fixed claims and proof evidence

The Protocol framework separates a mathematical model, an implementation relation,
a fixed requested property and evidence for that property. Construction and
installation produce evidence under explicit premises; they do not change the
requested event, bound, adversary or experiment to fit a proof.

The concrete IR claim vocabulary retains typed requests, capability/registry
descriptions, mathematical expressions and proof records. The native frontend
continues to publish source requests. A public promise's declaration coverage,
interface conformance and a proof of a fixed security claim are distinct judgments.
A direct kernel-checked proof may establish a claim without using registered laws;
that does not discharge an unrelated unproved public promise.

Pure and effectful meanings use their appropriate judgments. No purity annotation
alone proves totality. Outcomes retain stopped behavior and shared service state.
Logical binders and mathematical interpretations must be associated before runtime
erasure; names and hashes alone cannot justify a semantic installation.

The old concrete subject/compiled/byte endpoint installations and report join are
retired. No compiled security endpoint is currently installed. The generic
[construction framework](source-construction.md), independent mathematics and
[stored-declaration audits](declaration-records.md) remain available. Full
actual-source installation and new complete applications are the next boundaries.
