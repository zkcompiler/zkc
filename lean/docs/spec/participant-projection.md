# Source-to-participant correspondence

The source and constructed participant have independent meanings. A connection
proves that the actual participant implements the admitted source at the selected
role. It preserves all typed replies, stopped branches, the complete return row,
dynamic occurrences, history and live frames. Selecting the acceptance Boolean
is a later property-specific operation.

## Admission and the fixed proposition

`checkCompiled imported participant` checks transcript construction and exact
source-occurrence provenance against `Structured.Imported original`. The import
ties the typed program to its actual snapshot. `select` and `Selection.check`
fix the public input order, context, service replacement, declared sorts and
acceptance output. These finite checks do not assert execution correspondence.

The separate required proposition is
`ConnectionAdmission.Required program context mode participant`. Its selector
fixes the role, source-order input ABI, source-coordinate service capabilities
and occurrence routing from the admitted inputs and actual participant. Failed
selection means `False`; it does not remove the obligation. Successful selection
requires `SourceConnection.Connected`, including independent reached-source
coverage and full source-to-participant simulation for every model and physical
input environment.

This proposition is independent of the proof method. A root certificate is its
default implementation; any kernel-checked proof of the same fixed proposition
is admissible. The old unproved `project` walker has been removed. There is no
second structural traversal whose acceptance substitutes for a simulation.
`InputSelection` retains only the data mapping still used by scalar adapters.

## Checked derivations

`ConnectionCertificate.Certificate` pins the source body, signature, role,
input pattern, output locations, frame layout and target block before proof
search. It contains a checked normalization result and a finite typed alignment
derivation. Its generic soundness theorem yields `Original.Simulation`.

The source normal form preserves occurrences through nested repeats and
applications. `ConnectionLibrary.Bundle` retains reachable declaration/role
templates with their exact bodies and complete signatures. Application rules
check the target prefix and extent, caller/callee frame, full returned row and
continuation. Repeats are checked symbolically at their body interface; runtime
iteration counts are not unrolled into separate proofs. Pure calls may return
the incoming history cell.

The root assembler derives input layouts, capabilities, routes, return decoding
and independent source coverage. Coverage is proved before routing, so an absent
route cannot justify a simulation merely because every execution refuses.
Producer and validator use this same interface. Theorems retain the complete
nominal return relation and profile history, including malformed-input refusal.

`derive_source_connection` proposes a constructed view and a typed root
derivation. Its native computation is untrusted proof search: the kernel checks
the resulting view correspondence, finite premises and derivation. Larger
consumers may use `derive_source_connection using root` to reuse an imported
certificate. Checked source syntax and exact-placement alignments are shared
behind declarations; this does not establish a general relocation theorem.

## Property consumers and receipts

Canonical authored pairs require both producer and validator connections.
Validator-only domain claims require the validator connection. Removing proof
data leaves the same required proposition and opens the claim. Transcript
construction, property mathematics, attribution text or a matching declaration
name cannot replace the missing link.

The same validator connection serves completeness and adversarial soundness,
but those properties have different premises. Honest-pair completeness relates
the actual producer and validator and proves success under the independent
relation and honest-input policy. Adversarial soundness covers all typed public
statements, arbitrary messages and histories; honest-input restrictions are
not assumptions on the adversary.

`RootConnection` supplies source reading, observation coherence, ABI readback,
full return/frame facts and acceptance agreement. Public Fiat–Shamir reading
has explicit profile and local-service restrictions. Source property libraries
provide honest-pair and No/escape/cost rules. They do not turn a partial
correctness proof that permits refusal into perfect completeness.

Actual generated roots include both SmallSumcheck and TwoSums participants,
randomized Schnorr, plain aggregate transport, retained Sigma validators and
GKR. SmallSumcheck and TwoSums use the same roots for canonical completeness and
scalar/charged soundness. GKR's canonical consumers also use the shared roots;
its remaining scalar/Common source presentation is counted separately and is
not claimed to have disappeared with its old connection certificates.

The older scalar consumers remain explicit adapters while retained clients are
migrated. Their equations preserve typed public values, proof suffixes, initial
history, lawful challenge handlers and stops. A scalar projection of occurrence
coordinates is not an equivalence to a fresh random oracle on nominal keys.
Native byte execution and commitment realization are separate stages with
their own codec, resource and computational assumptions.

## Controls and limits

`Tests.SourceConnectionControls` checks the actual Schnorr connection and changes
its arithmetic, reply sites, return selection and source association.
`Tests.SumcheckConnectionControls` exercises guards, loop bounds, carried values,
yields, qualified sites and helper arguments. `Tests.PlainConstruction` checks
nominal aggregate transport. Structural construction/occurrence refusals remain
separate tests. `TestsSecurity.SourceConnectionClaims` removes a required link
from an actual canonical receipt and checks that the unchanged claim opens.

A connection-builder refusal is a diagnostic control, not a theorem that the
candidate is semantically different or insecure. Swapped equality operands can
require a mathematical law that the default method does not search for. The
checked suffix rule accepts unused pure calculations; loop display labels may
also change when all actual occurrence templates stay fixed. Extra effects and
changed reached operations are not discarded. Negative controls require the
expected static diagnostic; resource exhaustion, interrupts and unrelated
errors do not count. The construction bridge records structural kernel refusals
and connection-method refusals with distinct evidence kinds.

The generic connection does not infer arbitrary mathematical invariants, prove
degree bounds, select a witness extractor or justify cryptographic assumptions.
Unsupported helper shapes or missing component laws remain explicit proof
obligations. Property and stage support must be established by their consumers,
not inferred from successful source correspondence alone.
