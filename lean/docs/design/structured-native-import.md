# Structured native import

The native compiler publishes the checked original source. The independent Lean
reader admits typed definitions, helper and callback signatures, nominal domains,
role scopes, captures, services and explicit outcomes against its selected semantic
environment. The exported row is data; admission produces the typed Region that
the shared semantics interprets directly.

Source identity must remain exact across mathematical installation. The frontend
owns checked source identities and logical associations; IR preserves the typed
semantic dependencies needed by downstream readers. Lean checks applicability of
the actual implementation theorem. It should not infer source meaning by parsing
display labels or reconstructing erased capture, argument or scope information.

Actual source, a reusable mathematical interface, a fixed security claim and
native execution are separate boundaries. Model-level construction proves neither
source elaboration nor generated-controller correspondence. Both actual-source
installation and complete controller integration remain open after retirement of
the old generated views and concrete endpoints.

See [structured source](../spec/structured-source.md), [common construction](../spec/source-construction.md)
and [support](../support.md). The native differential lane exercises actual compiler
exports and compares full scripted source results, stops and event order; no proof
is generated or installed by that check.
