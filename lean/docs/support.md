# Supported claims

This page describes the maintained formal scope after retirement of the previous
source/constructed/executable connection route. The [theorem ledger](../README.md#what-is-proved)
names checked claims; the [framework claims](../protocol/docs/CLAIMS.md) distinguish
generic results from model clients and open actual-source applications.

## Maintained foundation

The Program package owns the shared typed Region, Process, outcomes and execution.
The independent structured reader checks source signatures, nominal data, scoped
regions, helper linking, role visibility and supported service/primitive metadata.
Its ordinary and Oracle meanings interpret the same admitted Region directly.
There is no scalar-view normalization or second source frontend on this path.

The concrete primitive/profile environment remains explicit. Successfully decoding
a logical type or catalog row does not install its semantic interpretation. Unsupported
profiles refuse admission. Compiler annotations and exported hashes do not prove
purity, totality, law conformance or a security theorem.

## Shared proof construction

The Protocol package constructs upper and lower quantitative bounds over the actual
Region/Process meaning using reusable operation laws. The complete model clients
exercise finite loops, branches, stops, callbacks, shared state, dependent queries
and library theorem reuse. State, ordered history, return rows and stop reasons
remain in the judgments. See the [construction specification](spec/source-construction.md)
and [authoring guide](development/source-construction.md).

The Verification package also installs laws on actual admitted native exports. Its
arithmetic client reuses one named theorem at two calls; its shared-service client
retains ordered handles, state and reached stops; its finite-loop client supplies
one invariant for arbitrary runtime counts. Checked association rejects stale bodies,
and semantic controls refute swapped arguments/handles and ignored stops. These
are source-execution results, not compiled cryptographic security endpoints.

The complete generated query controller and complete protocol applications remain
subsequent work. A companion supplies mathematics and meaningful representation
or admissibility premises; structural slots, frames, cursors and continuations
belong in common infrastructure.

## Core package

The Core package keeps the re-founded core language: `elaborate` and its round trip,
admission (the check of facts on a normal form and the check of copies), projection to
role programs, the construction steps, a total executor, and their theorems. An admitted
program never performs an undefined operation; a protocol admitted as written never stops
for copies that differ and keeps the agreements of its header; a role program is the
protocol for that role; the scheme that the steps derive is complete when the interactive
protocol is. Its kernel checks compare elaboration and the steps with the tool's output on
the fixtures. It states no soundness, knowledge or zero-knowledge property, and its theorems
are not in the ledger; its declarations are audited in a workspace that also requires
Program. It is independent of the core model in IR. The [package guide](../core/README.md)
lists the theorems.

## Formal package

The Formal package states properties of admitted programs over Core's meaning. It relates
the model of a package's rows in an arithmetic to the model that runs, for the operations
that pass its test, with the laws of the BLS12-381 curve as named hypotheses, and gives
rules for proving that every run returns an accepted value along a region. Its two clients
are completeness of one derived Schnorr scheme under those hypotheses and an invariant of
ten rounds of one Sumcheck package; neither is a soundness result. Its theorems are not in
the ledger. The [package guide](../formal/README.md) states the scope.

## Frontend package

The Frontend package is the compiler of the source language. It has no theorem: what it
emits is admitted by Core at every compilation, and its behaviour is tested.

## Independent mathematics

Retained libraries include algebraic rounds, multilinear table laws, commitment
and opening models, finite sampling and quantitative security interfaces. Optional
ArkLib results retain their explicit experiment and hardness premises. The Clean
adapter proves its flat mathematical export properties. These results do not by
themselves prove a compiled native verifier, runtime, backend or production kernel.

## Withdrawn endpoints

The previous generated Schnorr/Sumcheck/GKR and other source/compiled/byte endpoint
installations, scalar Common views, normal-form presentations, subject manifests,
bridge generators and joined assurance reports are removed. Their proof terms are
available in repository history, not in an alternate supported package. The current
registry has no installed native security endpoints. This deliberately narrows
formal support rather than substituting assumptions or vacuous claims.

Native program bytes, source correspondence, construction exports and execution
continue to have their independently specified native contracts. Formal adaptation
must establish new exact connections before claiming their security properties.

## Validation boundaries

- Package/import audits enforce source ownership, pinned dependencies and maintained targets.
- Declaration extraction inspects actual stored constants, private bodies, references and axioms.
- The theorem ledger checks statement locks and documentation citations.
- Standalone clients exercise public package APIs through real Lake dependencies.
- Source admission/execution compares compiler exports with the independent SSA and Lean
  interpreters, including ordered service replies and semantic stops. Its generous capacities
  do not assert equal instruction accounting between interpreters.

Timeouts, resource exhaustion and crashes are failures or incomplete validation,
never successful semantic refusals. Declaration metadata and passing execution
tests are not source correspondence or security proofs.
