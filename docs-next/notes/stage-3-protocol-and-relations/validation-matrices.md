## 1. Audit basis and reading rules

This ledger tests the integrated
[target semantic model](target-semantic-model.md) against the
[Stage 3 charter](charter.md), the
[Stage 3 entry contract](../stage-2-transitions/stage-3-entry-contract.md), the
[equal-resolution candidate critique](candidate-models.md), the selected
[Protocol IR Architecture](../../project/protocol-ir-architecture.md), and the
selected
[Transition and Bridge Architecture](../../project/transition-and-bridge-architecture.md).
It is deliberately redundant with the target model at the seam level. A
clean-room reviewer should be able to find an omitted input, authority cycle,
identity collision, or consumer overreach from these tables without inferring
it from prose elsewhere.

The tables use these rules:

1. A semantic subject, a checked result, an effect occurrence, a transport
   object, and a process-local capability are different categories.
2. `H(domain, regime, preimage)` means a domain-separated digest over the
   regime-defined injective canonical semantic encoding. It does not mean an
   MLIR printer digest or a transport digest.
3. An identity-bearing reference never contains a live capability. A
   transition consumes the reference and a matching capability as separate
   inputs.
4. `Authenticated<T>` means physical form, declared dependency preimages, and
   claimed identity have been recomputed. It does not authorize semantic use.
5. `Admitted<T>` is an opaque immutable process-local capability over the exact
   checked basis. Serialization, raw copying, mutation, reopen, or unmediated
   FFI ends that authority.
6. A result marked **direct** is recomputed from the complete closed input set.
   A result marked **later theorem** requires a separately owned theorem or
   model basis. Neither label is a security claim.
7. A codec, encoder, decoder, framing rule, sampler, or pure function in a
   semantic preimage is canonical data: either a closed finite typed term with
   declared totality evidence or a content-addressed contract ref with exact
   contract regime, regime-qualified content ID, ABI, and typed
   regime-qualified direct dependency IDs. A live function, implementation
   pointer, or checker capability is always a separate operation input.
8. The Protocol family's unique physically canonical v0 carrier is the one-root
   MLIR PIR graph. Every satellite is instead one finite canonical algebraic
   value under its owner regime; any accepted transport profile must decode it
   totally, losslessly, and with an explicit tag. A transport spelling cannot
   add meaning or become a second Protocol model.
9. The outcome abbreviations used below are:

   ```text
   A = Affirmative
   N = Negative(reason, retained facts)
   U = Unsupported(exact construct or question)
   C = CannotAnswer(missing named semantic input or basis)
   R = Refused(missing authority or prohibited invocation)
   M = Malformed(exact framing or structural defect)
   F = CheckerFailure(no semantic conclusion)
   ```

`N` is a successful semantic result. `U`, `C`, `R`, `M`, and `F` are not
negative judgments. A table listing possible outcomes does not require an
implementation to use one global result type.

Protocol owns canonical values, message bytes and wire codecs, event order,
transcript atoms and framing inputs, challenges, claims, checks, failures, and
terminals. Interface owns only external naming, lossless packaging, entry
selection, and typed application roles. Relation-specific maps belong to
`RelationBinding`, not `application_bindings`.

Even a successful Interface decode is not a complete Core invocation. It may
produce the public-`Statement` assignment subset and the payload occurrences
of proof-channel messages, but it cannot invent the remaining public/private
`CoreInvocationInputs`, decompose an arbitrary proof payload into
`ProverObligationOutput` bindings, choose secret inputs, construct a
`RandomnessReplay`, or decide the five-cause prover-binding precedence. Stage
4B/Realization must map exact endpoint and supplier results into that closed
grammar and prove agreement.

### 7.6 Invocation grammar and nonproduction precedence

| Layer or step | Exact check or transition | Outcome boundary |
|---|---|---|
| Invocation maps | `public_inputs` is total over every public input-port occurrence with one canonical same-domain value. `private_inputs` is total over every private input-port occurrence with one exact-owner, same-domain `RoleSecretInputValue` | Omission, addition, ordinal alias, duplicate, domain mismatch, or owner mismatch is M; no Core outcome forms |
| Prover-trace structure | Records are nondecreasing by `BeforeFirstEvent < PreAction(schedule rank)` and retain supplied order at one boundary; every obligation/output ordinal exists and every output is canonical in the exact declared domain | Unknown ref, out-of-range ordinal, wrong domain/value, boundary-order violation, or unknown record form is M, not nonproduction |
| Randomness-replay structure | Records follow the exact execution-attempt order: Core schedule, then obligation-basis order inside one pre-action. Fresh consumes public and private attempts; FS consumes only private Core randomness | Missing, reordered, mismatched, extra, wrong-domain, wrong-source, correlation/tag/index mismatch, or invalid conditional transition is M and yields no semantic conclusion; replay is a deterministic witness, not randomness authority |
| 1. Before source | At the first reached record for an obligation before its source boundary, select `EarlyOutput(that ordinal)` | First selected cause ends execution as the exact `ProverDidNotProduce` ref |
| 2. Inactive source | At the source boundary compute `EventAttempted` first; if false, the first record for that obligation there selects `UnexpectedOutput(that ordinal)` | No successful binding is consumed and the source action does not occur |
| 3. Duplicate shape | If attempted, inspect same-boundary records in supplied order; the first repeated ordinal selects `DuplicateOutput(that ordinal)` | It precedes private sampling and missing-output selection |
| 4. Private sampling | If duplicate-free, attempt private randomness in the identity-bearing basis order; the first failed attempt selects `PrivateSamplingFailed(that randomness)` | It precedes missing-output selection and action; the exact replay record is consumed |
| 5. Missing shape | After all required private samples succeed, scan required output ordinals in increasing order; select `MissingOutput(the least absent ordinal)` | No partial successful binding or event action occurs |
| 6. Successful bind | Only when no cause above was selected, bind every output once in ordinal order and enter the event action phase | These outputs are the only same-event values now legal in the kind-derived event inputs |
| After source or execution close | A later record for a closed source selects `UnexpectedOutput` when its boundary is reached. Prover records residual after a terminal or earlier nonproduction never replace that outcome | Residual prover records make `AcceptProtocol` false because its consumed prover-record count must equal the complete trace; residual randomness records instead make the invocation malformed and mint no Core record |

This precedence is Core semantics. A Plan, endpoint adapter, Interface decoder,
or realization cannot reorder it or reinterpret a structurally malformed trace
as a semantic nonproduction cause.

### 8.3 Hidden-input substitution probe

For every deterministic row above, hold all declared inputs fixed and vary the
host resolver, carrier spelling, tool build, theorem database, compiler,
registry, cache, provider set, local policy, and process. The normative outcome
must remain unchanged. If it changes, the varying input must either enter the
closed contract under its owning regime or the operation is not yet a valid
semantic contract. A capability may differ because the issuer process differs;
the underlying semantic outcome may not.
