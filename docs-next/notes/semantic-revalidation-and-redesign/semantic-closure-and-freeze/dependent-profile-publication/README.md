# Dependent Semantic-Profile Publication

> **Kind:** Temporary research-package contract and execution record
> **State:** Freeze candidate assembled; independent review pending
> **Authority:** None. Durable semantics and published profile sources belong
> to their named domain owners.
> **Deletion rule:** Absorb retained conclusions into durable owner pages and
> delete this package before documentation cutover.

## Objective

Publish independently reconstructible semantic-language profiles for the
dependent Interface/Plan, endpoint, Relations, and Analysis meanings without
changing the six already published upstream PIR profile bodies.

Publication is not a transcription exercise. Before a profile is formed, this
package repairs any ownership split that would make its declaration grammar,
direct-use imports, supported-kind set, or law source incomplete. A profile is
published only after two independent compilers reconstruct identical complete
body bytes and typed IDs.

## Selected dependency barriers

The work is bottom-up and divided by semantic dependency, not by file:

1. **Publication substrate and graph ownership.** Generalize the source-bound
   publication format without changing existing PIR bytes. OIR owns one
   complete source-independent endpoint graph grammar and its local admission
   laws. PIR owns source classification, owner reads, extraction, and source
   authority. Process-local capabilities are not portable supported subjects.
2. **Interface and endpoint profiles.** Publish Interface/Plan, the OIR
   endpoint graph, the PIR endpoint source view, and the OIR projection
   relation. The source view imports every profile whose declarations it
   actually opens; the projection relation imports both compared languages.
3. **Relations profile.** Publish the exact Relations semantic-subject set and
   its body/law dispatch. Profile-local publication catalogs are distinct from
   Relations module-declaration contracts. Relations directly imports every
   PIR profile whose owner views or declarations its laws interpret.
4. **Analysis profiles.** Publish the import-free kernel, then the bounded
   property, transport, theorem-source validation, incremental-composition,
   and composition-source-validation profiles. Every supported-kind set is an
   explicit canonical sequence; no set subtraction or host dispatcher is a
   publication source.
5. **Integrated freeze candidate.** Reproduce all identities, exercise local
   and downstream rotation, run holdouts and the uncapped aggregate, and then
   request one bounded independent freeze review.

## Required repairs and falsifiers

- Move every endpoint target-graph declaration and local invariant to OIR;
  remove shadow body definitions from the PIR source-view appendix.
- Give the endpoint source-view profile one explicit supported-kind catalog.
  Portable owner-supplement and source-envelope subjects are listed; live
  bearers, adapters, and capabilities remain process-local and unprofiled.
- Derive every direct import from exact declaration references and reject a
  missing, surplus, transitive-only, or cyclic edge.
- Preserve byte identity for all six published upstream PIR profiles while
  extending the publication source format to other owner namespaces.
- Require every supported subject kind to resolve one body compiler, at least
  one law, one evaluator signature, and one failure schema.
- Reject a Relations publication that confuses module contract kinds with
  profile-supported semantic subjects or omits its publication catalogs.
- Publish explicit Analysis kind sequences and reject host-derived set
  subtraction, cross-branch imports, backward validation imports, and an
  unsupported body-schema row.
- Mutating one owner fragment rotates that profile and exactly its downstream
  closure; a sibling or unrelated profile remains byte-identical.
- No manifest, owner fragment, or law source contains its own expected ID.

## Research routing retained from independent review

The current publication does not absorb unrelated future research into stable
profile identities:

- serializable checked handoff belongs at the later Realization/deployment

  remain explicit;
- the IVC theorem attachment, digest coverage, continuation-family uniformity,
  outstanding-obligation typing, and CycleFold same-step guardrail have durable
  semantic attachment points, but theorem activation waits for an exact
  source-pinned consumer;
- derived or large algorithmic Oracles, preprocessing, duplex endpoint and
  public-setup siblings, SR/RBR families, and vendor transcript compatibility
  remain separate post-freeze research packages; and
- finite-cover discharge is the first preferred Analysis implementation
  opportunity after publication because it can yield a genuinely
  hypothesis-free finite judgment without strengthening a theorem claim.

These routes are not forgotten work. They are excluded here because adding an
unresearched family to a supposedly closed profile would weaken publication,
not complete it.

## Ordered post-freeze research program

The freeze is followed by evidence pressure, not by immediate vocabulary
growth. The current order is:

1. **Cold protocol holdouts.** Validate WHIR constructively, then analyze
   Circle STARKs, WARPfold, multiparty Sumcheck, and transparent SNARKs over
   Galois rings from their primary sources without consulting a prewritten
   correspondence map. Preserve any failed frozen encoding before repair.
2. **Holdout adjudication and bounded refreeze.** Reopen only a shared owner
   boundary contradicted by a source-faithful holdout. Owner-local profiles or
   intentional v0 exclusions do not rotate the kernel. Rerun only affected
   descendants and holdouts after a repair.
3. **Finite-cover Analysis activation.** Implement the selected checked
   finite-cover discharge for fixed-extractor universal correctness. Its exit
   result is one genuinely hypothesis-free finite judgment, not an
   asymptotic, cryptographic, or implementation claim.
4. **Oracle and preprocessing extensions.** Research verifier-derived query
   plans, algorithmic large carriers, and pre-invocation preprocessing as
   separate candidates. Promote a shared primitive only when at least two
   materially different source families need the same law; otherwise retain
   a profile or module.
5. **Transcript and endpoint completion.** Research the duplex Plan-material,
   endpoint, and public-setup siblings together with an explicit stance on
   vendor byte compatibility. Semantic equivalence and byte compatibility
   remain separate relations.
6. **Transport and deployment.** Design serializable checked handoff at the
   Realization boundary while retaining same-process one-use handoff as the
   causal default and ordinary readmission as the degraded portable path.
7. **Security-property families.** Activate state-restoration and
   round-by-round families, recursive-composition theorem attachments, and
   their quantitative assumptions only from exact source-pinned consumers.

Each item is its own research package with a source ledger, explicit target
question, strongest required evidence depth, negative controls, promotion or
deferral decision, and nonclaims. Later items may move earlier only when a cold
holdout exposes them as a prerequisite.

## Exit criteria

This package closes only when:

1. every dependent profile has one complete durable owner-source manifest;
2. two independent compilers agree on all body bytes, typed references,
   imports, closures, and published identity records;
3. the six upstream PIR identities are unchanged;
4. every required falsifier and same-boundary positive control passes;
5. owner indexes, document manifest, links, terminology, and whitespace are
   clean;
6. the complete uncapped aggregate passes at the checkpoint commit; and
7. one bounded independent review has no unresolved freeze blocker.

Passing this package establishes profile reconstruction and bounded semantic
closure only. It proves no cryptographic theorem, compiler conformance,
runtime correctness, or production readiness.
