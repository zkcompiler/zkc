# Recursive Composition Research Contract

> **Kind:** Temporary research contract
> **State:** Completed
> **Authority:** None

## Decision question

What is the smallest owner-separated extension that lets zkc state and check
the finite prerequisites of recursive composition while preventing a one-step
correspondence result from being misreported as an IVC, PCD, folding, or
accumulation theorem?

## Candidate space

The research compares four boundary shapes:

1. **No new laws.** Keep one-step recurrence as the only modeled proposition
   and leave every multi-step statement external.
2. **One universal recursion subject.** Add a root that owns accumulator state,
   handoff, recurrence, decision, and theorem meaning.
3. **Owner-separated boundary laws.** Add structural coverage and uniformity
   checks, typed derived obligations, and an Analysis theorem-application
   family using the existing basis, support, validation, and judgment subjects
   while retaining existing PIR, Relations, and Realization ownership.
4. **Serializable causal authority.** Permit a checked portable object to
   recreate the same causal proposition after transport.

Candidates are tested for source fidelity, authority cycles, identity
stability, replay honesty, finite checkability, and whether they collapse a
runtime occurrence into a theorem.

## Required executable cases

The focused evaluator must include:

- refusal of an imported instance occurrence that is neither discharged at
  the current step nor digest-bound into an exactly carried discharged root;
- an affirmative two-source-to-one-target handoff preparation;
- affirmative value re-admission after serialization but refusal of the
  same-process causal handoff join;
- refusal of a continuation target whose semantic structure depends on a
  prior runtime instance value;
- refusal of a carried-obligations-discharged or hypothesis-free report while
  an accumulator or decider obligation remains outstanding;
- one affirmative, exact two-run/two-instance `EquationGrounding` intake with
  slot, owner, occurrence, equality, and extra-clause mutations; and
- a CycleFold guardrail that requires the companion curve-operation instance
  to be created, strictness-checked, public-I/O-bound to the primary fold, and
  folded inside the same step.
- exact purpose-bound export of the recurrence and binding-coverage results as
  owner-local Relations sources, followed by an exact two-slot Analysis
  manifest/support join; copied, partial, missing, cross-coordinate, and wrong-
  family inputs must refuse.

Every mutation requires a positive control at the same boundary. A finite
Python model is evidence about the selected distinctions, not an implementation
or proof of the durable owner operations.

## Exit criteria

The package closes only when:

1. all six boundary questions have one selected disposition and named owner;
2. the executable cases and their mutations pass one bounded gate;
3. a multi-step theorem cannot be formed from recurrence records alone;
4. serialization cannot recreate same-process causal authority;
5. the selected laws are absorbed into durable owners with exact nonclaims;
6. dependent profile-publication inputs are updated for every changed owner;
7. one independent falsification review is adjudicated; and
8. no unresolved finding changes the stable upstream PIR profiles already
   published.

All eight criteria are satisfied at package closure. The profile-publication
criterion means that the exact Relations and Analysis profile inputs have been
updated and made ready for the next bottom-up publication package; it does not
claim that those dependent profile IDs were already published here.
