## Decision question

Can the selected target architecture reach owner-profile publication without
undefined identity inputs, contradictory profile bodies, cross-run
correspondence, nondeterministic support outcomes, or malformed normative
rendering?

This package may repair owner-local laws and rotate their future profiles. It
does not publish final profile IDs, activate downstream architecture, or add a
new semantic owner.

## Confirmed closure obligations

The preflight treats the following as hypotheses to falsify against the live
tree before editing and as required repairs when confirmed:

1. one run-grounding evaluation must bind every public and confidential
   run-bearing operand to the identical invocation and completed record;
2. extractor counterfactual rights need one closed vocabulary whose cases have
   operational laws;
3. theorem-family contracts need one canonical body source rather than a false
   byte-equality claim between duplicated expansions;
4. every identity-bearing Analysis failure partition needs one exact denotation;
5. endpoint support classification needs a total phased dispatch and a
   deterministic reason set for every authenticated construction family;
6. construction profiles must terminate in Foundation-owned canonical carrier
   and failure types rather than undefined local aliases; and
7. normative code blocks, type projections, failure triggers, and load-bearing
   nonclaims must render and resolve unambiguously.

Each repair stays with its existing owner. None, if completed as scoped,
requires reopening the Interactive Core, Plan, Relations, Analysis, OIR, or
Realization factorization.

## Identity and migration effects

The repair is intentionally pre-freeze. Law changes rotate the future
Relations, Analysis, endpoint-view, and construction profiles that import
them. No already-published target identity is preserved by compatibility
aliases. Executable expected digests remain demoted evidence until owner
profiles are published and independently reconstructed.

## Exit criteria

The preflight closes only when:

1. all confirmed obligations above have one unambiguous durable owner;
2. every required probe has been executed or has an explicit reason it belongs
   to a later dependency barrier;
3. no known blocker remains before stable upstream owner-profile publication,
   and every dependent-profile blocker is named in the readiness record;
4. every changed durable page passes link, manifest, terminology, fence, and
   whitespace checks;
5. all changed stable-upstream surfaces pass their owner and joined-boundary
   gates, while the complete uncapped aggregate remains a global freeze exit
   condition; and
6. one focused independent review reports either no blocker or a fully
   adjudicated counterexample.

Repeated review of an unchanged green surface is outside this package.
