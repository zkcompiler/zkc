## 2. Preserved failed attempts

### 2.1 Treat the proof Oracle as an Oracle statement

**Attempt.** Map both `O_0` and proof-sent `O_1` through Relations'
`LogicalOracleTarget`, giving each a relation Oracle material assignment.

**Failure.** `LogicalOracleTarget` forms only for
`InitialOracle + LogicalAccess`. `O_1` is source-semantically a
`ProverOracle` published after `alpha_0`. Reclassifying it would change origin,
causality, supply authority, and transcript position.

**Adjudication.** Preserve `O_1` as a ProverOracle. The honest Plan uses one
site-local carrier value both for its Oracle move and a
`DerivedWitnessExport`. A Relations `PlanWitnessBinding` maps that export to
the folded-code relation's private witness. Public query/answer facts remain
Core facts.

**Disposition.** Existing owner seams suffice. This is evidence that the
initial-Oracle restriction is correct, not a request to widen it.

### 2.2 Create the folded claim before the next prover message

**Attempt.** Apply the first claim reduction immediately after the shift coin,
before `h_1`, to mirror an informal “claim state at the beginning of the next
round.”

**Failure.** The exact next target `sigma_1` contains
`g_0(z_shift)`, which the verifier obtains from an Oracle query in the source
decision phase. Moving a public query before `h_1` would disclose it to the
prover and enlarge the source strategy view. Omitting the value would leave a
partially grounded relation instance.

**Adjudication.** Keep every Oracle query after the last prover publication and
apply the structural reduction in the decision phase after the answer exists.
The output claim is not a prover-readable runtime value; it is exact semantic
bookkeeping for the verified transformation. The reduction declaration still
records the original publication/challenge ordering used by strong
Fiat--Shamir.

**Disposition.** Existing execution order and claim semantics suffice. No
query-visibility exception or symbolic runtime value is added.

### 2.3 Apply Fiat--Shamir directly to logical Oracles

**Attempt.** Attach the canonical framed transcript construction directly to
the Fresh WHIR Core while leaving both Oracles in `LogicalAccess` mode.

**Failure.** A logical publication exposes only a fixation marker, not a
carrier-derived commitment. The later challenge-dependent queries do not bind
the entire prover Oracle in a noninteractive execution. Direct transcript
admission would therefore not establish the commitment/opening interaction
required by the usual IOP-to-argument route.

**Adjudication.** First run the exact checked Oracle-commitment construction,
then run the checked Fiat--Shamir construction on the transformed Core. The
source and target Protocols remain distinct and linked by checked relations.

**Disposition.** Existing construction factorization suffices. BCS and
Fiat--Shamir security remain unactivated Analysis obligations.

### 2.4 Represent every practical WHIR parameter with finite carriers

**Attempt.** Treat the finite constructive member as evidence that all WHIR
Oracle sizes inhabit the v0 Core.

**Failure.** Every frozen Oracle has an explicit maximum of `2^14` entries and
must also satisfy Foundation size bounds. Practical and asymptotic WHIR
families can exceed this limit by orders of magnitude.

**Adjudication.** Keep the exact finite member as constructive evidence and
state family-wide large-carrier support as open. A later package will compare
explicit large carriers, algorithmic Oracles, and verifier-derived query plans.

**Disposition.** Intentional finite v0 boundary for this holdout. It becomes a
shared defect only if the declared v0 product scope requires those larger
members or a second source family proves one reusable missing law.

### 2.5 Import Theorem 5.2 through a citation

**Attempt.** Attach a generic round-by-round soundness label and the paper URL
to the structural Protocol.

**Failure.** The theorem concludes a vector of stage-specific errors under
exact list-decoding, distance, and mutual-correlated-agreement premises. The
paper proves one regime and treats broader regimes conditionally or
conjecturally. The published Analysis profiles do not contain this exact
experiment/property/theorem schema.

**Adjudication.** Leave every property result `NotEvaluated`. Route a
source-pinned WHIR round-by-round property and theorem profile to Analysis,
with separate theorem-truth/provenance subjects for the proved and
conjecture-dependent regimes.

**Disposition.** `ProfileOrModule`. No Protocol, Plan, Relations, or shared
Analysis-kernel change is required.

## 6. Retained work and promotion decision

The holdout causes **no shared model edit and no profile identity rotation**.
It opens two bounded future packages:

1. a WHIR-specific round-by-round Analysis property and theorem-source profile
   with proved and conjecture-dependent regimes separated; and
2. the already-planned cross-family large/algorithmic Oracle resource study.

An executable finite WHIR witness is not currently required. The constructive
mapping selected one unambiguous owner path and the negative matrix does not
leave competing shared designs. Promotion to executable depth becomes useful
only if implementation begins, if another holdout contradicts the proof-Oracle
grounding seam, or if a reviewer produces a concrete trace that the written
owner laws cannot distinguish.

## 7. Reopening conditions

Reopen the shared candidate only if one of the following is demonstrated:

- a source-faithful proof Oracle cannot use one site-identical Plan move/export
  value without exposing its carrier or duplicating authority;
- delaying non-observable claim bookkeeping until decision time changes an
  Analysis experiment or source transcript property;
- the checked commitment construction cannot preserve WHIR's grouped logical
  access and exact repeated query occurrences;
- an exact WHIR theorem application requires an adversary or observation not
  expressible by owner-local Analysis profiles;
- the finite Oracle ceiling contradicts the selected v0 product scope rather
  than merely excluding large members; or
- an executable negative mutation passes the same admission or
  correspondence contract as the positive case.

Absent one of these counterexamples, WHIR is evidence for the selected owner
factorization, not a reason to redesign it.
