# Finite-cover and query-plan semantic reclosure

Status: bounded reclosure complete; independent peer review pending. This note
records the work contract; it is not specification authority and is deleted
after its durable conclusions and evidence have been absorbed.

## Objective

Close the semantic gaps exposed by independent review in the checked finite-
cover Analysis lane and the verifier-derived query-plan lane before either is
used as a premise for larger-carrier research.

The package preserves the selected architecture:

- a finite cover discharges a raw universal only through separately checked
  coverage, quotient-factorization, and success-transfer obligations; and
- a verifier-derived query plan is a finite, non-answer-adaptive elaboration
  description for an independently formed and admitted flat Core, never a new
  runtime Oracle or protocol observation.

## Required closure

### Finite cover

1. Make the generic family contract and the active property-family row have
   exactly the same fields and law sorts.
2. Replace sampled raw-carrier congruence with an explicit universal quotient-
   factorization obligation. The obligation binds the exact raw predicate,
   normalization, representative embedding, candidate, algebraic profile, and
   canonical representative stream.
3. Bind every checker contract to the exact semantic operation it checks. An
   operation label alone is not a binding.
4. Derive the representative set independently from verifier acceptance, and
   retain mutations that distinguish finite coverage from universal
   factorization and representative success.

### Verifier-derived query plans

1. Use the Foundation operational outcome partition. Source-declared semantic
   terminals remain program/Core results; evaluator exhaustion and checker
   inconsistency do not become source semantics.
2. Derive componentwise elaboration bounds and make evaluator limits external
   to program identity.
3. Make algebraic assumptions explicit profiles. This package admits a prime-
   field profile and leaves future rings to separately identified profiles.
4. Close answer-dependence analysis over local steps, nested calls, logical-use
   activation, requested indices, and prior logical results. Reject only flows
   that can influence query control; allow answer-derived values in value-only
   computation.
5. Compute visibility through the full nested dependency closure.
6. Check the elaboration against an independently supplied, admitted flat Core
   rather than deriving the target Core identity from the candidate map itself.
7. Add an executable activation-and-prior-result witness, plus mutations for
   activation taint, index taint, transitive visibility, malformed algebra,
   partial arithmetic, target-Core substitution, and map substitution.

## Completion gates

The package is complete only when:

- durable Analysis and PIR pages state the closed contracts without duplicate
  or contradictory vocabulary;
- the two bounded instruments and their independent paths pass;
- semantic-profile publication and documentation structure checks pass;
- focused mutation tests fail closed at the intended boundary;
- the package records explicit nonclaims for theorem applicability, security,
  large carriers, answer-adaptive plans, and implementation conformance; and
- the shared worktree is handed off as one committed checkpoint.

Full release-freeze replay is not part of this bounded package unless a focused
gate reveals cross-owner breakage. Its very long Analysis replay is scheduled
evidence, not a prerequisite for every local semantic edit.
