## 1. Decision

The named folding, accumulation, and recursive-verification cases do not
justify a universal accumulator, folding-scheme, recursive-proof, or dynamic
child-Protocol subject. They preserve the existing ownership split:

```text
verifier-observable interaction        -> one flat InteractiveCore
challenge interpretation               -> Protocol
honest private construction            -> ProverPlan
claims, instances, and correspondence  -> Relations
endpoint presentation                  -> Interface and OIR
properties and theorem use             -> Analysis and Evidence
```

The shared missing capability is narrower. A Plan may need to derive a
private continuation value after an exact accepting terminal even though the
source interaction contains no later prover publication. The selected design
therefore adds accepted-terminal Plan recipes, atomic site-qualified private
outputs, and a causal same-process handoff to one later Plan's exact witness
ingress.

Public Plan parameters are not selected. Every frozen case can place a
verifier-relevant public value in Core or specialize a Plan with an admitted
constant. Reusable parametric Plans remain a separate authoring and deployment
question; convenience did not satisfy this package's semantic-promotion rule.

## 3. Selected lifecycle

The Plan-owned lifecycle has four relevant boundaries:

1. total private-material and private-randomness inputs are fixed before an
   execution session is prepared;
2. the admitted Plan strategy adapter is the only strategy allowed to drive
   that session's Protocol generation;
3. an accepting terminal may atomically issue one exact continuation arm,
   containing every guaranteed decision-derived export and every export
   derived at that terminal; and
4. one issued output may be consumed exactly once as a fresh witness-ingress
   occurrence of one target Plan execution.

Randomness is revealed only at its first declared actual demand. This is an
access and causality law, not a claim about sampling or distribution. Plan
generation and continuation capabilities are live, noncopyable,
nonserializable, and absent from every semantic identity. Replay never mints
them.

Core acceptance and Plan continuation success remain distinct. If terminal
derivation fails, the accepted Protocol record remains accepted, but no
partial private arm or retry authority is issued.

## 4. Exact cross-run recurrence

Value equality alone is insufficient. The selected finite recurrence combines
two separately checked propositions:

```text
private lane
  source relation witness occurrence
    -> finalized source Plan export occurrence
    -> one-use Plan handoff
    -> fresh target WitnessIngress occurrence
    -> target relation witness occurrence

public lane
  source run public output
    -> source RelationInstance public slot
    -> target RelationInstance public slot
    -> target run Statement binding

final join
  exact same source and target runs, instances, slots, and live authorities
```

The private lane requires a finalized source even when the selected export was
originally computed at a decision. The continuation capability supplies the
exact sealed-decision-export to active-continuation-output occurrence mapping;
equal values cannot replace it.

The public lane uses one exact grounding equation with an exhaustive
three-equality chain and exact source/target roles. Unrelated equalities,
self-equalities, confidential or artifact inputs, extra dynamic sources,
cross-run substitutions, and equal-but-distinct instance occurrences are not
recurrence evidence. The final result is nonidentified and process-local.

This establishes one finite causal step only. It does not establish relation
satisfaction, fold preservation, accumulation correctness, a decider theorem,
unbounded induction, or an incremental-verifiable-computation theorem.

## 5. Endpoint and recursive-verification boundary

The ordinary Plan-specialized prover endpoint remains public-proof oriented.
A distinct continuation-prover purpose adds the static, terminal-indexed
private-output contract and the exact recipe closure needed to construct each
possible arm. OIR owns the canonical static endpoint graph and contract body;
PIR owns runtime Plan generation, continuation, and handoff. OIR does not
project live private values and cannot recreate a Plan capability.

Serialized storage, network transport, decoding, and cross-process supplier
provenance belong to Realization. A future receipt may establish those facts,
but it cannot be treated as the direct same-process causal handoff selected
here.

Verifier-in-circuit recursion is a finite typed relation predicate over the
prior proof value and the imported verifier computation. The outer Core does
not invoke a child Protocol. The apparent setup cycle is broken by source-
faithful asymmetric construction order plus a separate setup/key
correspondence proposition; no semantic identity contains itself.

## 7. Validation and remaining gate

The finite Plan-continuation evaluator passes 52 executable tests, including
18 invoked mutation probes, across five distinct family shapes. It
independently reconstructs the static OIR contract and mutates strategy,
continuation, source-occurrence, handoff, recurrence, replay, and projection
boundaries. It is structural falsification evidence, not a source algorithm,
formal proof, implementation, or property judgment. In particular, it does
not execute the complete owner-level two-slot `EquationGrounding` intake; that
remains an explicit evidence obligation rather than an inferred result from
the evaluator's finite recurrence model.

This package closes at semantic-target scope only. Complete owner-profile
preimages and independently reconstructible profile identities remain
unpublished for affected PIR, Relations, and OIR owners. Independent profile
and identity freeze must therefore precede any claim of persistent semantic
identity, implementation migration, normative cutover, or holdout result that
depends on a frozen target.

## 8. Nonclaims and reopening conditions

No result here establishes correctness, completeness, soundness, knowledge,
zero knowledge, classical- or quantum-random-oracle applicability,
post-quantum closure, setup trust, recursive composition, performance,
implementation support, or migration readiness.

Reopen the semantic selection only if a source-faithful finite case requires
verifier-visible post-terminal behavior, a private dependency unavailable to
the closed Plan grammar, a cross-run causal path not expressible by the two
selected lanes, a recursive verifier that cannot be represented by one finite
typed relation, or an actual identity/authority cycle. Authoring convenience,
implementation reuse, and equal sample values are not reopening evidence.
