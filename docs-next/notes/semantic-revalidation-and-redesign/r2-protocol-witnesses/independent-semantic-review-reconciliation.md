## 5. Family decision: bounded experiment, not root replacement

The review correctly identifies pressure from size-indexed protocols. Its
suggested family-first root is not yet justified. The durable invariant remains:

```text
CoreId = Hash(exact InteractiveCore body)
```

Authoring route, schema identity, and index do not enter `CoreId`. Distinct
schemas or hand-authored and generated routes that produce the same body must
produce the same Core identity.

The bounded experiment now implements an optional `IndexedCoreSchema` above
exact Cores:

```text
IndexedCoreSchema + canonical finite index
        |
        | deterministic bounded elaboration
        v
candidate InteractiveCore body
        |
        +--> unchanged AuthenticateCore
        +--> unchanged AdmitCore
        v
CheckedCoreElaborationAt(SchemaId, index, CoreId)
```

This object is intentionally not called `CoreFamily`. An unbounded
mathematical protocol family remains an Analysis subject. A bounded schema can
establish exact generation of one member; it cannot establish relation,
algorithm, experiment, quantitative, or asymptotic correspondence.

One shared closed grammar handles both shapes. Its complete AST, finite index
domain, and static output/work expansion bound enter `SchemaId`; the selected
profile fixes the generic interpreter. The grammar contains typed natural,
name, reference, and finite-sequence expressions plus `Static` and finite
index-bound `Repeat`. Its identity-bearing descriptor authenticates the
complete formation and admission contract, is closed over every accepted
grammar node, and states the Core-field mappings, evaluation order, publication
zip, sizing, and concrete-admission delegation. Omitting a node is rejected;
a changed formation or mapping law rotates the profile identity.
Constitutional caps cover command nesting, finite index product, every emitted
Core lane, and interpreted command steps.
One pre-encoding carrier meter additionally charges every grammar node and
tuple slot with exact total-node, depth, and sequence-width limits, while an
all-fiber preflight refuses oversized range materialization before admission.
It has no family-kind dispatch, opaque generator node, recursion, or dynamic
topology. Grouped and flattened FRI ASTs have different schema identities but
elaborate to the same exact Core IDs at equal indices.

Six FRI fibers through each of those two program structures and three
sumcheck fibers pass ordinary concrete Core admission, exact Fresh and
Fiat--Shamir construction, execution, and same-Core checking. Hand-authored
representatives equal generated Core bodies and identities. Malformed command
aggregates, undeclared repeat axes, runtime-dependent topology, static bound
overflow, and concrete reference/order defects are refused. Occurrence-clause
counts are derived from the AST rather than asserted by family-specific code.
The all-index theorem API is an unconditional unsupported sentinel: it records
the experiment's explicit nonclaim and is not counted as falsification
evidence.

The result supports the architecture but does not yet select a durable PIR
satellite. It shows that one compact bounded grammar can remove repetition for
these two shapes without replacing exact Core authority. It does not show that
preprocessing, derived-oracle, recursive, data-dependent, or unbounded-family
topologies fit the grammar, nor that a finite schema establishes a family or
security theorem. Durable adoption still requires an owner, consumers, profile
publication, and a decision about whether the authoring surface belongs in PIR
or remains compiler machinery.

## 6. Consolidation judgment

The durable redesign contains `40,896` lines at the reviewed committed
checkpoint, versus `23,689` at the first redesign carry. The growth is real,
but not all of it is anticipatory schema: executable Foundation, active Core
and Fiat--Shamir laws, OIR, and Relations account for substantial necessary
growth. Analysis is the clearest overextended active region, while the generic
Compiler design was already large before this growth.

The correct budget is semantic rather than numeric. A new durable definition
must have:

1. one exact owner;
2. a current named consumer or demonstrated kernel necessity;
3. a falsification hook or explicit unexercised status;
4. no copied schema or ledger;
5. same-change retirement or supersession of a prior owner; and
6. a clear temporary-note absorption effect.

Immediate consolidation priorities are:

- rewrite active architecture decisions as current decision, rationale,
  owner links, and reversal conditions, without complete historical schemas;
- publish one complete supported-kind/profile catalog per owner;
- make Foundation the single owner of common noncompletion meanings while
  leaving each domain's completed payload and permitted subset domain-owned;
- replace the duplicated transition-owner ledger with an owner link and
  compact derived summary;
- hold the generic Compiler candidate/assessment machinery until a real
  multi-candidate transform consumes it; and
- promote only compact FRI laws, not the executable instrument or dossiers.

Owner-view consolidation is narrower than deletion. Shared coordinate,
manifest, projection, source-binding, and capability mechanics may be
extracted, but each domain retains its coordinate grammar, adequacy,
least-closure, disclosure, replay, and failure laws. In particular, the
existing `Observed([])`/`Unread`, `Inactive`/`NotReached`, terminal-output,
replay, qualification-basis, and four-role Relations distinctions remain
load-bearing.

Foundation evaluation contracts, resource precedence, charging behavior, and
canonical value identities already have consumers or executable pressure.
They are not blanket-pruning candidates. Relations embedding and peripheral
presentation/count machinery may be deferred only after an exact consumer and
preservation audit.
