# Post-Freeze Research Program

> **Kind:** Temporary dependency-ordered research charter
> **State:** Active; finite-cover Analysis and verifier-derived query-plan
> packages completed, algorithmic large carriers and Oracles next
> **Authority:** None. Durable semantics remain owned by their domain pages.
> **Entry condition:** The seventeen-profile candidate is holdout-stable at its
> declared evidence depths with no shared identity rotation.
> **Deletion rule:** Absorb selected meanings, decisions, evidence boundaries,
> and deferrals into durable owners, then delete this package before cutover.

## 1. Objective

Turn the frozen semantic architecture into stronger checked evidence and
carefully selected extensions without reopening stable identities by default.
Each package starts from a concrete unanswered judgment or repeated
source-family pressure, compares alternatives at equal resolution, and either
selects the smallest coherent extension or records an intentional boundary.

The program does not treat the freeze as proof of completeness. It treats it as
a stable baseline from which every later rotation has an explicit cause,
dependency cone, and validation record.

## 2. Method shared by every package

Each package must contain enough of the following record to make its decision
independently reviewable:

1. an exact question, scope, nonclaims, and exit decision;
2. a source ledger when external theory or a named protocol is material;
3. current-owner reconstruction before proposing a new primitive;
4. at least two equal-resolution candidates when a real design fork exists;
5. a positive inhabitant and source-shaped negative controls at the strongest
   useful evidence depth;
6. identity, authority, causality, visibility, resource, and failure analysis;
7. exact durable owners and the smallest rotation cone, if any;
8. bounded local gates followed by one package-level aggregate; and
9. one independent falsification pass at a material design boundary, not an
   unbounded review loop after every edit.

Passing executable checks is bounded evidence. It establishes neither theorem
truth nor cryptographic security unless an exact Analysis theorem path is also
formed and discharged.

## 4. Ordered research packages

### 4.1 Checked finite-cover Analysis activation

Activate the already selected finite-cover contract for
`FixedExtractorUniversalCorrectness` using the bounded Schnorr subject. Publish
the exact cover-reconstruction law, representative stream, portable extractor,
five checker bindings, three independent certificate goals, resource controls,
and replayable receipt. Rotate exactly the property profile and its dependent
closure.

Exit required one genuinely hypothesis-free affirmative finite judgment and
mutations for incomplete coverage, duplicate/reordered representatives,
congruence failure, transfer failure, checker mismatch, false extraction,
resource exhaustion, and attempted efficiency overclaim. The result discharges
only fixed-extractor correctness for the exact finite subject.

**Result:** completed. The exact ordinary arithmetic module, portable
algorithms, 308-member stream, three certificate judgments, and final empty-
hypothesis judgment are executable. An independently implemented enumerator
and encoder reproduce the stream digest and extractor outputs. Durable meaning
is absorbed; the temporary package remains only until program cleanup.

### 4.2 Verifier-derived words and query plans

This package is promoted ahead of generic resource work by the independent
holdout review. DEEP-ALI, STIR, and Circle FRI all use verifier-derived words or
query plans whose values are functions of previously authenticated Oracles,
claims, and challenges.

Compare:

- direct pure derivation at each query occurrence;
- an authenticated virtual-Oracle view with no publication event; and
- static elaboration into a closed query plan.

Reject any candidate that invents a prover publication, hides an ambient
callback, changes transcript influence, or loses source-query correlation.
Promote a shared primitive only if the same law is required by at least two
materially different families; otherwise retain exact owner-local profiles.

**Result:** completed. A separately identified finite word-program and logical
query-plan language now elaborates deterministically into one independently
admitted flat Core. Exact maps retain logical order, multiplicity, and source
leaves; no publication, transcript frame, commitment root, or runtime callback
was added. The profile is an additive Interaction-dependent leaf. The bounded
instrument covers four materially different source-shaped families with an
independent oracle and 25 tests. Exact paper correspondence and theorem claims
remain downstream obligations. The full temporary record is under
[`verifier-derived-query-plans/`](verifier-derived-query-plans/README.md).

### 4.3 Algorithmic large carriers and Oracles

WHIR and Circle reach the current finite Oracle ceiling, while Galois-ring
codes add large matrix/codeword pressure. Research canonical algorithmic
representations, streaming equality and access, replay, deterministic resource
refusal, and identity without materializing the entire carrier or accepting an
opaque evaluator.

This package must distinguish semantic finiteness from practical
materialization. It may raise a constitutional bound, add an exact algorithmic
carrier form, or retain the finite-v0 boundary. Performance motivation alone
cannot select a new semantic authority.

### 4.4 Checked preprocessing and setup

Research pre-invocation preprocessing as a separate lifecycle rather than an
in-protocol indexer. Sources include polynomial-commitment setup,
Galois-ring randomized code generation, and protocol-specific public
parameters.

The selected model must identify generation, distribution, trust,
randomness/provenance, validation, reuse, revocation, and invocation binding.
It must keep “transparent” distinct from “no setup” and must not infer code
distance or cryptographic binding from successful parameter construction.

### 4.5 Transcript and endpoint completion

Co-design the duplex construction-material Plan lane, public-setup sibling,
and endpoint/OIR sibling. Decide semantic equivalence independently from
vendor byte compatibility.

The package also owns:

- exact correspondence between WARPfold's relation-embedded hash chain and the
  admitted transcript framing;
- a set-difference challenge distribution and bounded retry/failure case for
  Circle's out-of-domain point;
- a separately pinned transcript source before composing the Galois-ring
  interactive protocol into a noninteractive subject; and
- exact endpoint support/refusal for every selected transcript family.

### 4.6 Transport and deployment

Research serializable checked handoff at the Realization boundary. Preserve
same-process one-use handoff as the causal default and ordinary value
readmission as the portable degraded path. Compare direct decider validation,
proof-of-decider validation, and explicit segment-digest binding without
turning transport bytes into causal authority.

### 4.7 Source-pinned security-property families

Activate properties only after their exact protocol and construction subjects
exist. The candidate set includes state restoration, round-by-round reasoning,
WHIR, Circle FRI/AIR, WARPfold and finite incremental composition,
Galois-ring code/commitment/PIOP claims, and recursive-composition theorem
attachments.

Every property remains a separate goal with exact experiment, adversary,
hypotheses, quantitative losses, theorem source, applicability, and truth
route. Soundness does not imply restoration; ROM does not imply QROM;
commitment verification does not imply binding; and finite evidence does not
imply an asymptotic theorem.

### 4.8 Multiparty regime study

Retain a separate charter for participant-indexed protocols. Before proposing
a schema, compare physical actors, local views, corruption structures,
communication and broadcast, correlated randomness, ideal functionalities,
abort/agreement, and real/ideal experiments across multiple source families.

The study also asks whether authenticated secret sharing can instantiate the
checked commitment abstraction for the virtual Sumcheck projection and what
exact premise relates a common-coin functionality to PublicEnvironment. It is
not an implementation commitment and does not reopen the two-role profile by
default.

## 5. Review-proposal disposition

The external research suggestions are retained at their dependency-appropriate
locations:

- verifier-derived words are promoted to the second package;
- the Oracle ceiling is the primary pressure for the large-carrier package;
- relation-embedded Fiat--Shamir correspondence and Circle set-difference
  sampling enter transcript completion;
- authenticated-sharing/commitment and common-coin correspondence enter the
  multiparty study;
- WARPfold's broad cross-system motivation remains unanswered until a concrete
  source protocol and decider exist; and
- source-pinned round-by-round, restoration, and incremental-composition
  properties remain in the security-property package rather than being
  inferred from structural support.

## 6. Program exit

This program closes only when every package above is completed, explicitly
deferred with a reopening condition, or moved into the product roadmap; every
selected change has one durable owner and complete profile publication; the
affected dependency cone has been independently reconstructed; all package
gates and one final bounded integration review pass; and temporary narratives
have been absorbed or deleted.

The program establishes no normative cutover, compiler/runtime support,
cryptographic security, wire compatibility, deployment readiness, or product
commitment.
