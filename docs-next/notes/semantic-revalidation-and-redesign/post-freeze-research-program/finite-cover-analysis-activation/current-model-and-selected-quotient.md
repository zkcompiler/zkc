# Current Model and Selected Quotient

> **Kind:** Temporary reconstruction and design record
> **State:** Selected; executable validation pending
> **Authority:** None

## 1. Exact subject

The source subject is the existing finite Schnorr fixture:

```text
p = 23
q = 11
g = 2
statement = 8
challenge set = {0,...,7}
```

One raw transcript contains four `Nat64` leaves:

```text
(statement, commitment, challenge, response)
```

The universal value is an ordered pair of such transcripts. Membership
requires the same exact statement and commitment, distinct challenges in
canonical increasing order, and exact Fresh verifier `Check` and `Terminal`
acceptance for both transcripts.

The current verifier does not require canonical group or scalar carriers. Its
effective equation is:

```text
g^(response mod q) mod p
  = (commitment * statement^(challenge mod q)) mod p
```

The challenge predicate already restricts each challenge to `{0,...,7}`. In
contrast, commitment is observed only modulo `p`, and response only modulo
`q`. The raw member set therefore contains many distinct `Nat64` encodings of
the same verifier-observable pair.

This is a fact about the repository fixture, not a claim about canonical
Schnorr encodings. The pinned CFRG draft requires an admitted instance and
typed scalar/group operations; it is used only to confirm the three-message
shape, verifier equation, and special-soundness motivation.

## 2. Rejected raw enumeration

The raw value type has eight `Nat64` leaves. Enumerating its complete product
before applying the member predicate is both unnecessary and an incorrect
model of the intended decision procedure. A smaller enumerator is sound only
if it is accompanied by an exact quotient law; merely observing that tests
pass on canonical values does not cover noncanonical accepted inputs.

## 3. Selected normalization

For raw member `r`, define `normalize(r)` fieldwise into the exact refined
representative carriers:

```text
statement  := statement mod 9
commitment := commitment mod 23
challenge  := challenge mod 8
response   := response mod 11
```

for each transcript. The representative type uses the same structural shape
with refined canonical ranges. The representative embedding is the identity
embedding of those refined naturals back into the raw `Nat64` fields.

Normalization is not allowed to repair nonmembers into members. The raw-domain
predicate is evaluated first and already fixes `statement=8` and challenges in
`{0,...,7}`, so reduction modulo `9` and `8` is identity on every member.
Coverage concerns every raw *member*, not every raw carrier value.

The quotient is selected because both operations relevant to the target factor
through it:

- verifier acceptance depends only on commitment modulo `23`, response modulo
  `11`, the already bounded challenge, and the exact statement anchor; and
- the selected extractor computes

```text
w = (z0 - z1) * inverse(c0 - c1) mod 11,
```

so its output depends only on the response and challenge residues. Output
congruence is exact witness equality.

## 4. Canonical representative stream

The canonical commitment residues in the subgroup generated by `2` are:

```text
1, 2, 3, 4, 6, 8, 9, 12, 13, 16, 18
```

For each commitment in ascending canonical order and each pair
`0 <= c0 < c1 < 8` in lexicographic order, the stream contains the unique
canonical responses `z0,z1 in {0,...,10}` accepted by the exact verifier for
statement `8`. The stream therefore contains:

```text
11 * choose(8,2) = 308
```

members. The exponent used to derive or check the subgroup carrier is an
enumeration index only. It is not an honest-prover nonce, private provenance,
or an additional witness field.

The stream algorithm is a deterministic state machine with one canonical
initial state, one yielded member and successor per nonterminal state, and one
terminal marker containing the count and ordered stream digest. The checker
must reject repeated state, duplicate or reordered member, premature terminal,
successor after terminal, count mismatch, or digest mismatch.

## 5. Portable arithmetic boundary

The extractor and normalization must be actual portable algorithms. Host code
that happens to implement the same formula cannot occupy their semantic
coordinates.

The selected dependency is a separate Foundation semantic module containing
small, exact, total deterministic natural modular-arithmetic primitives:

```text
natural.equal
natural.less-than
natural.modulo-positive
natural.subtract-modulo-positive
natural.multiply-modulo-positive
natural.power-modulo-positive
natural.inverse-modulo-coprime
```

Zero modulus and noninvertibility are typed semantic failures where relevant.
The module is owner-local and content-addressed. Adding it does not change the
Foundation grammar or `SemanticRegimeId`; only algorithms that cite the module
depend on its identity. A family-specific `schnorr.extract` primitive is not
selected because it would hide the formula the finite-cover target is meant to
bind and check.

## 6. Three certificate meanings

The checked representative run is not itself a proof that the quotient covers
the raw universal. Three independent goals remain mandatory:

1. **Coverage:** every raw member normalizes to an admitted representative;
   every representative embeds to the selected raw member; and the canonical
   stream reaches every representative exactly once.
2. **Congruence:** normalization and embedding preserve the input distinctions
   observed by the exact candidate, and the two candidate outputs are equal.
3. **Success transfer:** representative success and output equality imply the
   raw member-success predicate for every raw member in that class.

The first two modulo-factorization clauses rely on the exact denotations of the
selected arithmetic module and verifier predicate, not on sampled tests. The
finite checker exhausts the canonical residue classes and authenticates those
exact laws and algorithms. Its receipt is replay evidence, not a substitute
for any certificate capability.

## 7. Exact conclusion and nonclaims

The only new affirmative conclusion is:

```text
the exact response-difference portable extractor succeeds for every member of
the exact bounded Schnorr pair domain, under the exact selected quotient and
certificate set
```

It does not establish runtime complexity, uniformity across moduli or statement
lengths, a generic discrete-log extractor, existential special soundness for a
protocol family, or cryptographic security.
