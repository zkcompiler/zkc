## 2. Pre-closure adversarial findings

The candidate did not pass its first adversarial reading unchanged. The
following were substantive defects, not editorial preferences:

| Finding | Why it blocked closure |
|---|---|
| carrier structural parse required an authentication basis before recovering the claimed subjects | parsing and semantic authentication were circularly ordered, so the carrier could not expose the exact pair that authentication had to check |
| validation basis appeared inside semantic proposition and bridge identities | changing a certificate or checking method could change the identity of an unchanged mathematical proposition |
| relation satisfaction relied on a trusted evaluator callback | the callback had no closed request/response ABI, deterministic continuation law, or capability boundary, so an affirmative result depended on ambient authority |
| artifact and result surfaces used undefined or incompletely bounded types | artifact bytes, selectors, completion variants, rejection reasons, and limit outcomes could not be formed and checked from the written algebra alone |
| Plan prior-read admission accepted any earlier occurrence | syntactic position was weaker than the all-path K2 availability law, allowing a route to read a value absent on some reaching execution path |
| `RelationRunView` omitted transitive verifier-private influence | private influence through guards, checks, terminal dependencies, or reduction dependencies could leak into a supposedly public relation view |
| run-grounding accepted bare fact selectors without an expectation | the result promised value or state agreement even though most selectors named only a coordinate and supplied no relation-derived or explicit expected value |
| several completed propositions lacked closed result or coverage grammar | `PlanRealizesReason`, recursive whole-value coverage, artifact minimum-count checking, and lossy-use source binding could not be deterministically formed or replayed |
| bridge-law checking depended on an already admitted bridge | admission itself required the affirmative law check, creating a candidate/law/admission cycle |
| lossy-use checking conflated a portable source selector with live occurrence authority | an inert instance ID could not retain process generation or capability authority, so equal-valued occurrences were not safely distinguishable at a consumer |
| the first carrier probe crossed its selected dependency cut | it serialized the FS construction body, derived expected dispositions from the same reflected shape it checked, and used a shadow relation definition that put evaluator identity into definition identity |
| several indexes and local routes still described the pre-repair surface | readers could be directed to stale ownership or status statements even when the candidate pages themselves had been corrected |

The algebraic-closure defects, executable false-positive seams, evidence-model
drift, and stale routing were all treated as closure blockers. A passing
positive fixture was not accepted as evidence against these counterexamples.

## 3. Repairs and adjudication

The selected architecture was retained, but its laws were tightened at the
owning boundaries:

1. Carrier reading is now two-stage. A basis-independent structural read
   recovers the claimed `InteractiveCore` and `Protocol`; authentication then
   checks that exact pair under the supplied K1 basis. Parsing grants no
   semantic authority.
2. Stable definition/model, refinement, and value-bridge identities contain
   semantic propositions only. Law declarations, certificates, evidence,
   controls, and evaluator limits are external validation basis bound into a
   checked result.
3. Relation satisfaction now uses a closed deterministic command machine with
   exact `start` and `resume` algorithms. Relations owns query resolution and
   supplies only typed responses; the portable machine receives no ambient
   material capability. Positive and negative decisions remain distinct from
   malformed, unsupported, limit, noncompletion, and checker-failure results.
4. Artifact interpretation now derives exact byte and field types from an
   admitted profile, uses typed artifact value identities, closes selector and
   completion grammars, and gives rejection and deterministic-limit outcomes
   exact types. Observed-empty remains distinct from unread.
5. Plan formation is separate from `PlanRealizes`. Realization checks every
   prior source read against K2's all-reaching-path availability rule rather
   than accepting an occurrence merely because it has a lower ordinal.
6. The PIR-owned `RelationRunView` is public-only after transitive influence
   closure across inputs, guards, predicates, messages, Oracle activity,
   checks, reductions, and terminal dependencies. Owner issuance additionally
   requires the exact invocation and completed replay-qualified execution.
7. Run grounding now uses a closed check algebra: relation-bound values,
   explicitly typed expected values, two closed expected-meta families, and
   presence-only claim/reduction histories. A coordinate alone no longer
   asserts agreement, and a relation-grounding question must actually read its
   named instance.
8. Whole-surface coverage now has one recursive finite selector-partition law;
   Plan realization has a complete deterministic negative algebra; artifact
   minimum counts have a profile-wide checked question; and every counted
   lossy bridge use at the closed run-grounded seam has a complete premise
   equation, contract-owned source-anchor check, and exact owner-derived use
   selection before its selected count can be consumed. Structural Plan and artifact mappings do
   not inherit an unformable live-source premise or quantitative claim.
9. Bridge validation now follows the acyclic order authenticated candidate,
   law check, admission, then application. A certificate lane consumes exact
   law and assumption admission authority rather than dereferencing inert IDs.
   A lossy premise's portable result remains separate from its owner-local live
   source binding; an explicit consumer join checks owner, field occurrence,
   generation, and capability before reuse.
10. The carrier fixture now serializes only its bounded graph, authenticates FS
   construction bodies through a separate dependency environment, compares a
   literal frozen disposition manifest against reflected shape, and uses an
   inert typed relation-definition reference. It still does not implement the
   durable fourteen-field carrier.
11. Stale ownership, phase, and routing text was aligned to the repaired
   candidate, and the durable manifest and local-target checks were rerun.

The repair did not add a generic purpose-view abstraction, a shadow Protocol,
or an Analysis-owned satisfaction hook. `ProtocolRelationBinding` and
`PlanWitnessBinding` remain separate; the latter binds one source-ID-free
`PlanWitnessSurface`. Equivalence, embedding, lossy value projection,
relation refinement, and commitment grounding remain different semantic
questions.

## 4. Bounded executable evidence

The K3-B instrument executes 29 finite tests. Its positive inhabitants include
Schnorr, a Fresh protocol with verifier-private input, a native Oracle
interaction, R1CS-shaped attachment, and Nova-shaped folding. R1CS and Nova
are structural fixtures only. The instrument also exercises same-boundary
mutations for Interface assignment and Statement coverage, Plan admission and
all-path reads, witness binding, public run-view attenuation, value-bridge
lane separation, artifact grounding, and a tagged round trip of the bounded
legacy K2 executable carrier shape with its construction body supplied through
an external dependency environment. It does not round-trip the durable
fourteen-field target carrier.

The executable fixes corresponding to the pre-closure findings are observable
as negative tests: a branch-local prior value cannot satisfy a route reached
through another branch, and transitive verifier-private influence cannot be
exported through a relation run view. The generic Plan projection and ambient
Analysis premise callback were removed from the instrument rather than
credited as unselected design.

Passing these tests demonstrates finite constructibility and rejection at the
named boundaries only. It does not promote fixture labels, Python objects, or
host callbacks into target semantics.

## 6. Independent audit disposition

The bounded adversarial audit that produced the findings in Section 2 was
adjudicated finding by finding. A focused read after repair reported no
remaining blocker in the repaired carrier, identity/validation,
bridge-admission, lossy-use authority, satisfaction, artifact, Plan-read, or
public-run-view seams. Narrow editorial
suggestions that improved exactness were absorbed; no positive review was
treated as evidence for cryptographic claims.

One additional cold-review attempt yielded no adjudicable report inside its
bounded window and therefore contributes no evidence to this validation
record. A later completed independent review found one executable-evidence
defect rather than a normative K2 defect: the Python `Invocation` pre-supplied
Fresh challenge values, so a host closure could bypass `ProverView` and
correlate an earlier move with a future coin. The instrument was repaired to
remove coins from invocation data and identity, invoke a runtime resolver only
at the challenge occurrence, replay from the recorded historical value, and
exercise issuance order, missing resolution, and resolver-independent
invocation identity. The 57-case K2 gate above includes those regressions.
This does not claim Python process isolation or universal noncommunication.
Closure rests on the explicit repairs and reproducible gates above, not on the
non-result attempt or the later positive rerun alone.
