## 8. Selected semantic-context repair

### 8.1 Rejected alternatives

A single integrated global regime would authenticate every domain law, but a
local Analysis family or PIR effect would rotate unrelated Protocol,
Relations, and OIR identities. It would also need either a large inline root
or a root/module fixpoint. Separate per-domain regimes would localize change,
but ordinary cross-domain references would then require a new translation and
compatibility authority at every boundary. Both are worse than the selected
model.

The selected model is:

```text
SemanticLanguageProfileBody = R {
  0: profile_family,
  1: revision,
  2: sorted-unique imported_profile_ids,
  3: nonempty sorted-unique supported_subject_kinds,
  4: sorted kind-indexed local_declaration_catalogs,
  5: exact semantic_law_source
}

SemanticLanguageProfileId =
  ContentId<"foundation.semantic-language-profile", SemanticLanguageProfileBody>

ProfiledSemanticBody(profile_id, domain_body) = R {
  0: profile_id,
  1: domain_body
}

EffectiveSemanticContext(subject) =
  (authenticated Foundation mechanism regime,
   subject's exact profile ID and no-extra profile-preimage closure)
```

The profile is an ordinary same-regime semantic subject, not a declaration in
an otherwise mutable module. Its import DAG contains only exact upstream
profile IDs and may not receive extra supplied preimages. Its own finite
declarations use local kind/ordinal coordinates; imported declarations use an
explicit `(profile ID, kind, ordinal)` coordinate into the authenticated import
closure. A profile never cites a subject that uses it, its own ID, evidence, a
local capability, a policy decision, or an ordinary module root. Consequently,
adding an unrelated sibling declaration, module payload, or module import
cannot rotate the profile or create a profile-to-module-to-profile identity
cycle. Subject-specific ordinary module references remain in the owning domain
body and are authenticated separately by that domain evaluator. A domain
evaluator advertises support for the exact authenticated profile and law
source; matching a family name or revision is insufficient. An explicit
checked compatibility edge is required between unequal profiles.

The selected repair uses independently evolvable profile owners and exact
import topology:

- K2 `PIRInteractionProfile`, `PIRTranscriptFSProfile`, and
  `PIRPublicSetupProfile`;
- K3-B `PIRInterfacePlanProfile` and `RelationsProfile`;
- K3-C Analysis kernel, bounded cryptographic property, AFK transport, and
  theorem-source-validation profiles; and
- K3-D OIR endpoint graph, PIR endpoint source view, OIR projection relation,
  and OIR projection validation profiles.

These are exact import cones, not one convenience bundle. In particular, the
Relations cone reaches Interface/Plan and the K2 Interaction and
Transcript/FS profiles, but not the K2 PublicSetup profile; public-setup
invocation views enter Analysis as separately authenticated owner inputs. The
K3-D cone begins at Interface/Plan and does not contain Relations.

The selected Foundation regime rotates once because it gains the generic
profile formation and support mechanism. Afterwards, changing one domain
profile rotates only subjects that use it and downstream profiles that import
it. Existing typed cross-domain references remain under one K1 basis.

The K3-E executable instantiates deterministic finite profile objects for this
graph, but this note and its evidence do not publish the durable owner-local
six-field profile preimages or their full typed IDs. Every durable owner must
publish those independently reconstructible preimages before any dependent K4
ID is treated as persistent and before K5 freeze. The current Analysis
executable pins are symbolic-law and host-dispatch surrogates and must not be
promoted into the ideal typed Analysis profile identities.

This selection is consistent with two useful, non-authoritative design
analogies. MLIR lets dialects own their versions and records only dialects
actually used by a bytecode artifact, rather than versioning the entire IR
universe together. Content identifiers similarly combine typed content
interpretation with a hash rather than treating digest bytes as sufficient
meaning. These analogies support local, exact-used semantic profiles; they do
not substitute for the zkc laws above.
