## Purpose

The case studies examine mechanisms, trust boundaries, proof obligations,
path-dependent constraints, and failed abstractions that matter to zkc. They
are not ranked by adoption or maturity, and no analogy is accepted without an
explicit transfer limit.

Only primary papers, official specifications and documentation, and official
source repositories are used as factual sources.

## Reading rule

Every transfer candidate must answer:

1. What exact semantic object does the source system define?
2. What is proved, checked, validated, implemented, measured, or merely
   described?
3. What remains in its trusted base or external correspondence obligation?
4. Which mechanism can transfer to zkc without importing the source's semantic
   ontology?
5. Where does the analogy fail for interactive, probabilistic, adversarial,
   occurrence-sensitive Protocols?

Cross-case deductions are evaluated against the [design forces and
opportunities](../design-forces-and-opportunities.md), not treated as votes for
one candidate.
